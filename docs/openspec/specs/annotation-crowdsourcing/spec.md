## 新增需求

### 需求：企业可以创建和管理标注任务包
系统须允许企业用户创建标注任务包，配置计价模式（按件/按包）、单价、总数据条数、外部任务ID。

#### 场景：创建标注任务包草稿
- **当** 企业用户填写标注任务包表单（标题、描述、计价模式、单价、总条数、外部任务ID）并保存为草稿
- **则** 系统须创建状态为"草稿"的标注任务包（task_type=ANNOTATION）

#### 场景：发布标注任务包
- **当** 企业用户在草稿状态的标注任务包点击"发布"
- **则** 系统须将任务包状态设为"已发布"并对兼职可见

#### 场景：关闭标注任务包
- **当** 企业用户关闭一个已发布的标注任务包
- **则** 系统须将任务包状态设为"已关闭"并停止接受新抢单

### 需求：企业可以管理标注任务包的批次
系统须允许企业用户为标注任务包创建批次，每个批次包含数据条数和外部批次ID。

#### 场景：为任务包添加批次
- **当** 企业用户为标注任务包添加一个批次（数据条数、外部批次ID）
- **则** 系统须保存批次并设置状态为"ACTIVE"

#### 场景：查看批次抢单情况
- **当** 企业用户查看批次列表
- **则** 系统须展示每个批次的抢单人数、数据条数、外部批次ID

### 需求：兼职可以浏览和抢单标注任务
系统须允许兼职在找活页面浏览标注任务，按批次抢单。

#### 场景：浏览标注任务
- **当** 兼职在找活页面筛选"标注任务"
- **则** 系统须展示所有已发布的标注任务包（task_type=ANNOTATION）

#### 场景：查看标注任务详情
- **当** 兼职点击标注任务卡片
- **则** 系统须展示任务包详情（标题、描述、计价模式、单价、总条数、批次列表），不展示地点、图片、班次时间

#### 场景：抢单（选择批次）
- **当** 兼职在标注任务详情页选择一个批次并点击"抢单"
- **则** 系统须创建状态为"待处理"的报名单（schedule_applications PENDING）

#### 场景：批次已满
- **当** 批次的抢单人数已达到上限
- **则** 系统须阻止新的抢单

### 需求：企业可以审核标注任务的报单
系统须允许企业用户审核标注任务的报单申请。

#### 场景：审核通过报单
- **当** 企业用户在待处理报单上点击"通过"
- **则** 系统须将报单状态设为"已通过"并生成任务单（annotation_task_orders PENDING）

#### 场景：审核拒绝报单
- **当** 企业用户在待处理报单上点击"拒绝"
- **则** 系统须将报单状态设为"已拒绝"

#### 场景：审核通过后不生成排班
- **当** 标注任务的报单审核通过
- **则** 系统须仅生成任务单，不生成schedule_shifts（排班），不创建attendance_records（考勤）

### 需求：任务单跟踪标注进度和状态
系统须通过任务单跟踪每个工人的标注进度和状态。

#### 场景：任务单状态流转
- **当** 报单审核通过
- **则** 系统须创建任务单，状态为"PENDING"（待标注）

#### 场景：外部系统回调标注完成
- **当** 外部标注系统回调标注完成（/api/external/annotation/submit）
- **则** 系统须将任务单状态设为"SUBMITTED"（已提交），更新已标注条数

#### 场景：外部系统回调质检通过
- **当** 外部标注系统回调质检通过（/api/external/annotation/quality-check，passed=true）
- **则** 系统须将任务单状态设为"COMPLETED"（已完成）并触发自动结算

#### 场景：外部系统回调质检不通过
- **当** 外部标注系统回调质检不通过（/api/external/annotation/quality-check，passed=false）
- **则** 系统须将任务单状态设为"REJECTED"（需重新标注）

### 需求：标注任务完成后自动结算
系统须在标注任务质检通过后自动计算报酬并入账工人余额。

#### 场景：按件计费结算
- **当** 标注任务计价模式为"按件"（PER_ITEM）且质检通过
- **则** 系统须计算 `已标注条数 × 单价` 作为结算金额，入账工人余额

#### 场景：按包计费结算
- **当** 标注任务计价模式为"按包"（PER_PACKAGE）且质检通过
- **则** 系统须使用固定金额作为结算金额，入账工人余额

#### 场景：结算后工人可提现
- **当** 标注任务结算完成
- **则** 工人可在C端小程序提现（复用现有提现流程）

### 需求：外部系统人员映射管理
系统须支持本系统与外部系统的工人ID映射。

#### 场景：新增人员映射
- **当** 企业用户新增外部系统人员映射（工人ID、外部系统类型、外部工人ID）
- **则** 系统须保存映射关系

#### 场景：回调时通过映射查找工人
- **当** 外部系统回调时提供external_worker_id
- **则** 系统须通过external_worker_mapping表查找对应的worker_id

### 需求：外部系统回调接口安全
系统须确保外部系统回调接口的安全性。

#### 场景：验证API Key
- **当** 外部系统调用回调接口
- **则** 系统须验证请求头中的X-Callback-Key是否与配置的API Key匹配

#### 场景：防止重复回调
- **当** 外部系统重复调用同一回调接口（相同的external_submission_id）
- **则** 系统须返回成功但不重复处理

### 需求：C端任务单管理
系统须允许兼职查看自己的标注任务单。

#### 场景：查看任务单列表
- **当** 兼职进入"我的任务单"页面
- **则** 系统须展示该工人的所有标注任务单（任务名称、批次、已标注条数、状态）

#### 场景：查看任务单详情
- **当** 兼职点击某个任务单
- **则** 系统须展示任务单详情（任务名称、批次信息、进度条、状态、外部标注平台跳转链接）
