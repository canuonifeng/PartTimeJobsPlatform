## 新增需求

### 需求：运营平台可配置企业账号后缀
系统须允许运营平台为企业设置专属账号后缀。

#### 场景：运营平台设置企业后缀
- **当** 运营人员在企业管理页面输入账号后缀（如 `acme`）并保存
- **则** 系统须将后缀存储到 `enterprises.email_suffix` 字段

#### 场景：后缀唯一性校验
- **当** 运营人员提交的账号后缀已被其他企业使用
- **则** 系统须拒绝保存并返回错误

#### 场景：新增企业时设置后缀
- **当** 运营人员新增企业时填写账号后缀
- **则** 系统须在创建企业时同时保存后缀

### 需求：企业端必须使用后缀格式登录
系统须要求企业端登录时使用 `前缀@后缀` 格式的用户名。

#### 场景：使用正确格式登录
- **当** 用户输入 `admin@acme` 和密码进行登录
- **则** 系统须解析后缀 `acme`，找到对应企业，使用 `admin` 作为用户名验证账号密码

#### 场景：不带后缀登录被拒绝
- **当** 用户输入不包含 `@` 的纯用户名进行登录
- **则** 系统须返回“用户名格式不正确，须使用 前缀@后缀 格式”

#### 场景：后缀不匹配任何企业
- **当** 用户输入的后缀在 `enterprises` 表中不存在
- **则** 系统须返回“账号后缀不正确”

#### 场景：账号不属于该企业
- **当** 用户输入的前缀对应的账号不属于后缀匹配的企业
- **则** 系统须返回“账号不属于该企业”
