# 标注任务管理 规格

## 需求

### REQ-AB-1: 企业端标注职位独立模块
**优先级**: P0

**描述**: 企业端 PC 将标注(ANNOTATION)职位与零工(WORK)职位拆分为独立管理模块，互不混杂。

**场景**:
- 场景 1：运营进入"标注任务"菜单 → 列表仅展示 task_type=ANNOTATION 的职位 → 支持标题/状态筛选 → 可新建、编辑、发布、下线、删除标注职位
- 场景 2：运营进入"零工招聘"菜单 → **仅展示 task_type=WORK 的职位，绝不混入标注职位** → 原零工能力不变（含班次/排班管理）
- 场景 3：在标注模块新建职位 → 表单默认任务类型=标注，只显示标注相关字段（计价方式/单价/任务总量），不显示零工时段等字段

**约束**:
- 两个模块路由独立、菜单独立；列表接口复用现有 /api/enterprise/jobs 的 taskType 参数，**前端强制固定 taskType 取值**（零工模块固定 WORK、标注模块固定 ANNOTATION），不得依赖用户手动筛选
- 标注职位的新建/编辑/发布/下线/删除复用现有 JobController 接口，不改契约

**验收标准**:
- [ ] 菜单出现"标注任务"与"零工招聘"两个独立入口，路由各自独立
- [ ] 零工招聘模块**只展示 WORK 职位**，标注职位绝不出现
- [ ] 标注模块列表只显示 ANNOTATION 职位
- [ ] 标注职位表单默认 ANNOTATION 类型且仅显示标注字段

### REQ-AB-2: 标注职位批次管理
**优先级**: P0

**描述**: 标注职位下提供批次维护能力：新建、编辑、上线、下线、查看进度。批次复用 job_schedules 表（标注批次不需要日期/时段）。每个批次必须有**批次代号**与**数据量**信息。

**场景**:
- 场景 1：进入某标注职位的"批次管理" → 展示该职位全部批次（**批次代号**/数据量/外部批次ID/状态/已抢数/已完成数/进度）
- 场景 2：新建批次 → 填写**批次代号**（必填）、**数据量**（必填，正整数）、外部批次ID（可选）→ 不要求日期/时段 → 创建成功，状态 ACTIVE
- 场景 3：编辑批次 → 修改批次代号/数据量/外部批次ID
- 场景 4：下线批次 → 状态置 CANCELLED → C端不再展示该批次、不可再抢；重新上线 → ACTIVE
- 场景 5：进度展示 → 该批次已完成任务单数 / 数据量（或已抢数）

**约束**:
- 批次仍以 job_schedules 行承载；schedule_date/start_time/end_time 允许为空（标注批次为 null）
- 批次状态沿用 job_schedules.status（ACTIVE/CANCELLED）
- 标注批次**批次代号写入 batch_code（必填）**、数据量写入 total_items（必填）、外部批次ID写入 external_batch_id（可选）
- 新建/编辑批次时 batchCode 与 totalItems 为空则拒绝保存（后端校验）
- 零工排班的日期/时段必填约束保持不变（由企业端表单校验，不改数据库 NOT NULL 或改后可空但零工侧仍校验）

**验收标准**:
- [ ] 标注职位下可进入批次管理，列表含批次代号/数据量/外部ID/状态/进度
- [ ] 新建批次无需日期/时段，批次代号+数据量必填，保存成功且状态 ACTIVE
- [ ] 批次代号/数据量缺失时保存被拒绝
- [ ] 编辑批次成功；下线后 C端不可见，重新上线恢复
- [ ] 进度数据真实（按任务单统计）

### REQ-AB-3: 批次上下线影响抢单
**优先级**: P1

**描述**: 批次下线后，C端标注详情不再展示该批次；已抢到的任务单不受影响。

**场景**:
- 场景 1：批次 CANCELLED → C端详情页批次列表不显示该批次 → 工人不可抢
- 场景 2：批次 CANCELLED 后重新 ACTIVE → 重新展示可抢
- 场景 3：批次下线不影响该批次已有任务单的完成/结算

**约束**:
- 抢单逻辑继续使用 jobScheduleMapper.findActiveByJobId（仅查 ACTIVE）
- 任务单与批次关联不变

**验收标准**:
- [ ] C端详情页批次展示与批次状态一致
- [ ] 下线批次不可抢、上线后可抢
