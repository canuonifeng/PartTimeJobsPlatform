# C端找活快捷筛选 规格

## 需求

### REQ-WF-1: 固定快捷筛选入口
**优先级**: P0

**描述**: C端找活页顶部快捷筛选固定为五个入口：全部 / 零工 / 标注 / 附近 / 急招。

**场景**:
- 场景 1：默认选中"全部" → 展示所有任务类型职位（现状行为）
- 场景 2：选"零工" → 仅展示 task_type=WORK 职位
- 场景 3：选"标注" → 仅展示 task_type=ANNOTATION 职位
- 场景 4：选"附近" → 按当前定位距离升序返回职位（无定位时保持现有行为）
- 场景 5：选"急招" → 仅展示 urgent=true 的职位

**约束**:
- 保留关键词搜索与分页；分类筛选（categoryId）可保留但不再是首屏唯一维度
- 快捷入口与后端搜索参数映射：全部(无taskType)、零工(WORK)、标注(ANNOTATION)、急招(urgent=true)、附近(sort=distance)

**验收标准**:
- [ ] 顶部固定五个入口，切换后列表正确过滤/排序
- [ ] 附近入口在有定位时按距离升序

### REQ-WF-2: 急招职位标记与筛选
**优先级**: P0

**描述**: 企业发布职位时可标记"急招"；C端"急招"入口展示所有 urgent=true 的已发布职位。

**场景**:
- 场景 1：企业新建/编辑职位时勾选"急招"开关 → 保存后 jobs.urgent=true
- 场景 2：C端选"急招" → 返回 urgent=true 且 PUBLISHED 的职位（不限任务类型）
- 场景 3：取消勾选保存 → urgent=false → 不再出现在急招列表

**约束**:
- jobs 表新增 urgent 字段（默认 false）
- 企业端 JobForm 增加"急招"开关（仅展示于标注与零工通用位置）
- C端 JobSummaryVO 增加 urgent 字段（前端已有预留）

**验收标准**:
- [ ] 企业端可勾选/取消急招并保存
- [ ] C端急招入口只显示 urgent=true 的已发布职位

### REQ-WF-3: 附近排序
**优先级**: P1

**描述**: "附近"入口按职位距当前定位的距离升序排列。

**场景**:
- 场景 1：已授权定位 → 选"附近" → 返回职位按 distanceKm 升序
- 场景 2：未授权定位 → 选"附近" → 按现有默认排序返回（不报错）

**约束**:
- 复用现有经纬度/距离计算；搜索接口增加排序参数（如 sort=distance）
- 距离升序与 taskType 过滤可叠加

**验收标准**:
- [ ] 附近入口有定位时按距离升序
