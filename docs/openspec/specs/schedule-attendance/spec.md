## 新增需求

### 需求：企业可创建排班模板
系统须允许企业用户创建可复用的排班模板，包含时段、位置和人数上限。

#### 场景：创建排班模板
- **当** 企业用户创建一个包含时段的排班模板
- **则** 系统须保存模板供后续岗位复用

### 需求：企业可为排班指派兼职
系统须允许企业用户将已录用的兼职指派到具体的排班时段。

#### 场景：指派兼职到排班时段
- **当** 企业用户将兼职指派到一个排班时段
- **则** 系统须记录该指派并通知兼职

### 需求：兼职可查看个人排班
系统须允许兼职查看被指派的排班和即将到来的工作安排。

#### 场景：查看个人排班
- **当** 兼职打开排班页面
- **则** 系统须展示即将到来的排班，包含日期、时间和位置

### 需求：兼职可打卡签到和签退
系统须允许兼职在小程序中打卡签到和签退，并带有位置校验。

#### 场景：签到成功
- **当** 兼职在岗位位置范围内且在排班时段内点击"签到"
- **则** 系统须记录签到时间及位置信息

#### 场景：签退成功
- **当** 兼职在排班结束后点击"签退"
- **则** 系统须记录签退时间并计算总工时

#### 场景：签到位置不在范围内
- **当** 兼职尝试在指定位置范围外签到
- **则** 系统须拒绝签到并提示位置错误

#### 场景：签到距离使用全局配置
- **当** 班次未设置 `locationRadius` 且平台配置了 `check_in_radius_meters`
- **则** 系统须使用 `check_in_radius_meters` 作为签到/签退距离阈值

### 需求：打卡签退可配置自动结算
系统须支持签退自动结算功能，开启后工人签退时自动完成薪资结算。

#### 场景：开启自动结算 + 企业余额充足
- **当** 平台配置 `auto_settle_attendance=true` 且企业余额足够
- **则** 工人签退时系统须自动结算：入账工人余额、扣减企业余额、发送"收入到账"通知

#### 场景：开启自动结算 + 企业余额不足
- **当** 平台配置 `auto_settle_attendance=true` 但企业余额不足
- **则** 系统须降级为 UNPAID 状态，不阻止签退

#### 场景：关闭自动结算
- **当** 平台配置 `auto_settle_attendance=false`
- **则** 工人签退后结算状态为 UNPAID，等待企业手动操作

#### 场景：自动结算成功弹窗
- **当** 签退自动结算成功
- **则** 前端须弹窗提示"已收到 ¥X 薪资，去提现？"并提供跳转提现页按钮

### 需求：企业可查看考勤报表
系统须提供考勤报表，展示每次排班的签到/签退时间、总工时和异常情况。

#### 场景：查看排班考勤
- **当** 企业用户打开某次排班的考勤页面
- **则** 系统须展示每位指派的兼职的签到/签退时间、状态和总工时
