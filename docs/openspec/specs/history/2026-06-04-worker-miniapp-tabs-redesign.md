# 工人端微信小程序 4 个 Tab 视觉改造设计

## 背景

当前项目 `worker-uniapp` 是工人端 UniApp 应用，目标端优先为微信小程序。用户提供了 C 端小程序完整设计稿，本次先落地 4 个主 Tab：首页、找活、消息、我的。

## 范围

改造现有 Tab 页面：

- `src/pages/index/index.vue`：首页 / 排班打卡
- `src/pages/jobs/jobList.vue`：找活 / 岗位列表
- `src/pages/message/message.vue`：消息
- `src/pages/profile/profile.vue`：我的 / 个人中心

不改造以下页面：

- 岗位详情
- 报名确认
- 收入明细
- 打卡记录
- 设置
- 登录页

## 目标

- 让 4 个 Tab 的视觉风格贴近设计稿。
- 保留现有路由、TabBar 和业务接口结构。
- 微信小程序优先，H5 仅作为兼容目标。
- 接口可用时优先展示真实数据，接口失败或数据为空时使用兜底示例数据，便于视觉验收。

## 设计系统

使用设计稿中的核心视觉语言：

- 主色：`#07c160`
- 主色深色：`#06ad56` / `#059a4c`
- 背景色：`#f5f5f5`
- 卡片色：`#ffffff`
- 薪资强调色：`#ff6b35`
- 周结蓝色：`#409dff`
- 警告色：`#ff9500`
- 危险色：`#fa5151`
- 文字主色：`#333333`
- 文字次色：`#666666`
- 辅助文字：`#999999`
- 卡片圆角：`24rpx`
- 标签圆角：`12rpx`
- 按钮圆角：`50rpx`
- 阴影：`0 4rpx 24rpx rgba(0, 0, 0, 0.06)`

CSS 以 `rpx` 为主，使用 `view`、`text`、`image`、`scroll-view` 等小程序兼容组件，避免 H5 专属标签和样式能力。

## 页面设计

### 首页

首页承接设计稿的“排班打卡”页面。

结构：

1. 顶部绿色渐变 Header
   - 问候语
   - 日期、星期、今日班次数
   - 三个统计块：本月工时、本月收入、出勤天数
2. 今日排班卡片
   - 支持多个今日班次
   - 展示岗位名称、状态、时间、地点、距离或兜底距离
   - 根据签到状态展示提示条
   - 签到和签退按钮沿用现有逻辑
3. 未来排班列表
   - 展示后续 5 条排班
   - “全部”跳转现有排班页

数据策略：

- 继续调用 `getMyTopShifts()`。
- 继续使用现有签到、签退接口。
- 如果未登录，展示登录引导。
- 如果接口失败或无排班，使用设计稿同款示例数据作为视觉兜底。

### 找活

找活页承接设计稿的“岗位列表”。

结构：

1. 顶部搜索栏
2. 横向分类标签
3. 岗位卡片列表
   - 左侧岗位图标或图片
   - 岗位名称
   - 薪资高亮
   - 地点和距离
   - 日结 / 周结标签
   - 企业名称
4. 下拉刷新和上拉加载更多保留

数据策略：

- 继续调用 `getJobs()`。
- 保留搜索、分类切换、定位参数、刷新和加载更多。
- 接口失败或无数据时展示示例岗位。
- 尽量兼容现有字段：`title`、`rates`、`minRate`、`maxRate`、`location`、`distanceKm`、`companyName`、`imageUrl`、`companyLogo`。

### 消息

消息页从空状态改为设计稿消息列表。

结构：

1. 顶部分段 Tab：系统通知、企业消息、报名反馈
2. 消息列表卡片
   - 图标头像
   - 消息来源
   - 时间
   - 摘要
   - 未读红点

数据策略：

- 当前先使用静态消息列表。
- 切换消息分类在本地过滤。
- 后续如新增消息接口，可替换为 API 数据源。

### 我的

我的页承接设计稿的个人中心。

结构：

1. 绿色渐变个人信息 Header
   - 头像
   - 姓名
   - 手机号
   - 实名认证状态
   - 累计收入、累计工时、出勤天数
2. 本月收入卡片
   - 本月收入
   - 待结算
   - 已结算
   - 查看明细跳转现有收入页
3. 菜单分组
   - 我的排班
   - 我的报名
   - 打卡记录
   - 收入明细
   - 电子合同
   - 技能认证
   - 意外保障
   - 邀请好友
   - 帮助中心
   - 设置
4. 退出登录保留

数据策略：

- 继续调用 `getProfile()`。
- 姓名、手机号、头像优先使用接口数据。
- 收入、工时、出勤天数、菜单右侧统计使用兜底展示。
- 现有可跳转页面继续跳转；暂不存在的页面点击时提示“功能建设中”。

## 组件与代码组织

本次优先控制变更范围，只改 4 个页面，不新增全局组件。

如果某些样式在 4 个页面重复，可以在页面内保持局部重复，避免过早抽象影响交付速度。后续全量 10 页改造时，再抽取公共卡片、标签、按钮、菜单项等组件。

## 交互与错误处理

- 接口失败不阻断页面渲染，展示兜底数据并保留用户可操作入口。
- 首页签到、签退失败继续使用现有 toast 错误提示。
- 找活定位失败时不阻断列表加载。
- 未登录场景保留登录引导。
- 无对应页面的菜单项显示 toast，不跳转无效路径。

## 验证

实现完成后运行：

```bash
npm run build:mp-weixin
```

验收重点：

- 微信小程序构建通过。
- 4 个 Tab 页面可正常打开。
- TabBar 路由不变。
- 首页签到 / 签退入口仍使用现有业务逻辑。
- 找活搜索、分类、刷新、加载更多仍可用。
- 页面视觉贴近设计稿。
