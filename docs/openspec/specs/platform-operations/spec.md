## 新增需求

### 需求1：运营人员可审核企业注册
系统须允许平台运营人员审核企业注册申请，批准或拒绝。

#### 场景：通过企业注册审核
- **当** 运营人员审核企业注册后点击"通过"
- **则** 系统须激活企业账号并通知企业管理员

#### 场景：拒绝企业注册
- **当** 运营人员审核企业注册后点击"拒绝"并填写原因
- **则** 系统须将企业状态设为"已拒绝"并通知企业管理员

### 需求2：运营人员可审核被举报的岗位
系统须允许平台运营人员审核因违规被举报的岗位。

#### 场景：下架违规岗位
- **当** 运营人员审核被举报岗位后点击"下架"
- **则** 系统须下架该岗位并通知企业

#### 场景：驳回举报
- **当** 运营人员审核后认定岗位合规
- **则** 系统须驳回举报并保持岗位正常发布

### 需求3：运营人员可查看数据看板
系统须提供全平台数据看板，展示活跃企业数、在招岗位数、注册兼职数、完成排班数和交易金额等核心指标。

#### 场景：查看平台数据看板
- **当** 运营人员打开数据看板页面
- **则** 系统须展示汇总指标及趋势图

### 需求4：运营人员可管理系统配置
系统须允许运营人员配置系统级设置，包括岗位分类、平台费率、通知模板。

#### 场景：更新岗位分类
- **当** 运营人员新增、编辑或删除岗位分类
- **则** 系统须全平台同步更新分类列表

#### 场景：配置平台费率
- **当** 运营人员设置平台佣金比例
- **则** 系统须将该比例应用到所有相关交易

### 需求5：运营人员可管理已审核企业
系统须提供企业管理功能，支持对已通过审核的企业进行查看、编辑、停用/启用操作。

#### 场景：查看企业列表
- **当** 运营人员打开企业管理页面
- **则** 系统须展示已注册企业列表，包含名称、联系人、电话、状态
- **且** 可按状态（ACTIVE/SUSPENDED）筛选

#### 场景：编辑企业信息
- **当** 运营人员编辑企业信息并保存
- **则** 系统须更新企业基本信息（名称、联系人、电话、地址等）

#### 场景：停用/启用企业
- **当** 运营人员停用某企业
- **则** 系统须将该企业状态设为 SUSPENDED，禁止其登录
- **当** 运营人员启用某企业
- **则** 系统须将该企业状态设为 ACTIVE，恢复其登录

### 需求6：运营人员可管理企业登录账号
系统须支持为每个企业创建和管理登录账号，企业员工通过这些账号登录企业端系统。

#### 场景：查看企业下账号列表
- **当** 运营人员点击某企业的"账号管理"
- **则** 系统须展示该企业下的所有登录账号（用户名、显示名、角色、状态）

#### 场景：为企业创建账号
- **当** 运营人员为企业新增账号并填写用户名、密码、显示名、角色
- **则** 系统须创建账号，密码 BCrypt 加密存储

#### 场景：编辑账号信息
- **当** 运营人员修改账号的显示名或角色
- **则** 系统须更新账号信息

#### 场景：重置密码
- **当** 运营人员重置某个账号的密码
- **则** 系统须更新密码为新的 BCrypt 加密值

#### 场景：删除账号
- **当** 运营人员删除某个账号
- **则** 系统须从数据库中移除该账号

### 需求7：企业注册审核通过后自动创建企业记录
系统须在注册审核通过时自动在 enterprises 表中创建企业记录。

#### 场景：审核通过同步创建企业
- **当** 运营人员通过企业注册申请
- **则** 系统须自动创建对应企业记录（状态 ACTIVE）
- **且** 企业记录关联原始注册申请的 registration_id

### 需求8：企业端登录从数据库读取账号
企业端（enterprise-service）的登录认证须从 enterprise_accounts 表读取，而非硬编码内存用户。

#### 场景：企业用户登录
- **当** 企业用户使用账号密码登录企业端系统
- **则** 系统须从 enterprise_accounts 表验证身份
- **且** 返回包含企业 ID 和角色的 JWT 令牌
