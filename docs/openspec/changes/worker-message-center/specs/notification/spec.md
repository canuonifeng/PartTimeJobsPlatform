## 新增需求

### 需求：工人端查看站内消息
系统须支持工人在 C 端消息页查看自己的站内消息。

#### 场景：查看我的消息列表
- **假如** 工人已登录
- **当** 工人进入消息页
- **则** 系统须返回该工人的消息列表
- **且** 消息须按创建时间倒序排列
- **且** 消息须包含标题、内容、分类、创建时间和已读状态

#### 场景：禁止查看他人消息
- **假如** 工人已登录
- **当** 工人请求消息列表
- **则** 系统只能返回当前登录工人的消息

### 需求：工人端消息分类展示
系统须支持将工人端消息按业务分类展示。

#### 场景：消息分类
- **当** 系统返回工人端消息
- **则** 每条消息须归属以下分类之一：系统通知、报名反馈、排班提醒、收入提现

### 需求：工人端标记消息已读
系统须支持工人将自己的消息标记为已读。

#### 场景：点击消息后标记已读
- **假如** 工人已登录且消息属于该工人
- **当** 工人点击未读消息
- **则** 系统须将该消息标记为已读
- **且** 再次查询时该消息不再显示未读标记

#### 场景：禁止标记他人消息
- **假如** 工人已登录
- **当** 工人尝试标记不属于自己的消息为已读
- **则** 系统须拒绝该操作

### 需求：关键业务事件生成工人站内消息
系统须在关键业务事件发生时为工人生成站内消息。

#### 场景：报名审核结果通知
- **当** 企业通过或拒绝工人的报名
- **则** 系统须为该工人生成报名反馈消息

#### 场景：排班通知
- **当** 工人的排班被生成、变更或取消
- **则** 系统须为该工人生成排班提醒消息

#### 场景：工资结算到账通知
- **当** 工人工资结算到账
- **则** 系统须为该工人生成收入提现消息

#### 场景：提现结果通知
- **当** 工人提现成功或失败
- **则** 系统须为该工人生成收入提现消息

#### 场景：实名审核结果通知
- **当** 工人实名审核状态变更为通过或拒绝
- **则** 系统须为该工人生成系统通知

#### 场景：开工前提醒
- **当** 工人排班即将开始
- **则** 系统须为该工人生成排班提醒消息
