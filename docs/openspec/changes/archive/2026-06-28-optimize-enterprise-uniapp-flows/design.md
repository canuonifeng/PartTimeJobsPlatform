## Context

企业端小程序已有完整的 5 步业务流（创建岗位 → 创建班次 → 审核报名 → 考勤确认 → 薪资结算），但页面分散在 Tab 2（招聘流程/timeline）和各独立管理页中，用户缺少按流程引导的操作路径。首页虽有快捷入口，但仅是一排按钮，无进度感和上下文连贯性。

当前 Tab 结构：
- Tab 1 工作台：统计卡片 + 快捷入口
- Tab 2 招聘：timeline 展示
- Tab 3 消息
- Tab 4 我的

岗位和班次的创建入口深埋在"招聘 → 岗位列表 → 发布岗位"的多步路径中。需要引入 AI 对话创建能力，让用户通过自然语言一句话完成创建，同时改造 Tabbar 添加快速入口。

## Goals / Non-Goals

**Goals:**
- 工作台首页改为"今日待办"模式，展示待处理事项卡片（报名审核/今日班次/待结算），每项可跳转
- Tab 2 招聘页改为流程概览，展示 5 步完整流程的汇总数据，每步可钻取到管理页
- 岗位创建成功后无缝跳转到班次创建页
- 报名审核页按班次分组，支持批量操作
- 考勤确认页增加待确认/已确认筛选，与结算状态联动
- 薪资结算页展示结算进度，与企业余额联动
- Tabbar 改为 5 项，中间 "+" 按钮凸起，点击进入 AI 对话页
- AI 对话页支持文字/语音/图片输入，通义千问识别意图后自动创建

**Non-Goals:**
- 不改变现有后端 API 的通用返回结构
- 不涉及数据库表结构变更
- 不改动 PC 管理端

## Decisions

1. **工作台与招聘页明确分工**：工作台聚焦"今日待办"（待处理事项卡片列表），招聘页聚焦"流程概览"（5 步流程汇总数据），不重复展示
   - 替代方案：两处都展示进度条 → 功能重叠，用户困惑，选择差异化
2. **岗位→班次跳转**：`jobForm.vue` 创建成功后，`uni.redirectTo` 到班次管理页（带 jobId），不返回列表
   - 替代方案：弹窗询问"是否创建班次" → 多一步操作，选择直接跳转
3. **报名按班次分组**：前端对 API 返回的报名列表按班次时间排序分组展示，不改动后端分页
   - 替代方案：后端新增分组 API → 过度设计，前端分组足够
4. **考勤与结算联动**：考勤确认页增加结算状态筛选标签，调用已有 API 的 `settlementStatus` 参数
   - 无需后端改动
5. **结算进度与余额**：薪资结算页顶部增加企业余额卡片，调用已有 `getBalance` API
6. **Tabbar 实现方式**：扩展现有 `EnterpriseTabBar` 组件，新增 `type: 'fab'` 配置项，中间按钮渲染为凸起圆形
   - 不使用原生 tabBar（无法实现凸起效果）
7. **Python 代理层**：FastAPI + `sse-starlette`，对接通义千问、阿里云 ASR、enterprise-service
   - 选择 FastAPI 而非 Flask 因其原生异步和 SSE 生态
8. **语音处理**：小程序录音上传 → Python 代理 → 阿里云 ASR → 文字 → 通义千问对话
9. **图片处理**：`uni.chooseImage` 上传 → Python 代理临时存储（24h 清理） → 通义千问 VL 识别

## Architecture

```
企业端小程序 (UniApp)
├── EnterpriseTabBar (5 tabs, 中间凸起 "+" AI 创建)
├── AI 对话页 (pages/aiChat/aiChat)
│   ├── 录音 (wx.getRecorderManager) → Python 代理 → 阿里云 ASR
│   ├── 拍照/选图 (uni.chooseImage) → Python 代理 → 通义千问 VL
│   ├── 文字输入 → SSE 流式对话
│   └── 结构化确认卡片 → 用户确认 → Python 代理调 enterprise-service
├── FlowGuide 组件 (首页卡片 + 流程页列表)
└── 优化后的业务页面 (工作台/招聘/报名/考勤/结算)

Python 代理层 (ai-proxy/, FastAPI)
├── POST /api/chat (SSE)  — 通义千问流式对话
├── POST /api/upload      — 图片/音频上传
├── 阿里云 ASR SDK        — 语音转文字
├── 通义千问 API           — qwen-max + qwen-vl-max
└── enterprise-service     — 创建/修改岗位班次
```

## Risks / Trade-offs

| Risk | Mitigation |
|------|-----------|
| 岗位→班次跳转可能让用户感到突兀 | 跳转时在班次页顶部显示 toast 提示"岗位已创建，请添加班次" |
| 流引导组件在首页和流程页两处出现，用户困惑 | 首页为卡片概览，流程页为列表详情，视觉差异化 |
| 报名按班次分组后列表可能变长 | 默认折叠，点击展开该班次的报名列表 |
| 通义千问 API 不稳定或延迟高 | 前端流式渲染掩盖部分延迟；设置超时兜底 |
| 语音识别准确率不足 | 前端展示 ASR 转写文本，用户可手动编辑再发送 |
| AI 识别意图错误 | 每个结构化卡片需用户确认后才执行；可文字修正 |
