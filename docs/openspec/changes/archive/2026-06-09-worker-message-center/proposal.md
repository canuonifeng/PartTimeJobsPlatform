# Worker Message Center Proposal

## Why

工人端当前消息页仍使用前端静态示例数据，无法反映报名审核、排班、收入、提现和实名审核等关键业务事件。工人需要在一个统一消息中心查看关键状态变化，减少遗漏上工、审核和资金相关信息的风险。

## What Changes

- 为工人端实现真实站内消息列表，替换静态 mock 数据。
- 明确第一版消息触发范围：报名审核结果、排班生成/变更/取消、工资结算到账、提现成功/失败、实名审核结果、开工前提醒。
- 支持消息分类展示：系统通知、报名反馈、排班提醒、收入提现。
- 支持未读标记和点击消息后标记已读。
- 复用现有 C 端通知接口和通知表能力，必要时补充字段、接口或迁移脚本。

## Capabilities

### New

- `notification`：工人端站内消息中心。

### Modified

- `notification`：扩展关键业务事件触发站内消息的场景。
- `worker-user`：工人端消息页从真实接口读取消息并展示未读状态。

## Impact

### Backend

- 主要影响 `c-service` 通知查询和工人端业务事件写通知。
- 可能影响企业端审核、排班、结算流程中写入工人通知的逻辑。
- 需要保证接口鉴权：工人只能查看和更新自己的消息。

### Frontend

- 主要影响 `worker-uniapp/src/pages/message/message.vue`。
- 需要新增或完善 `worker-uniapp/src/api/notifications.js`。
- 页面不再使用静态示例数据。

### Database

- 优先复用现有 `c_notification` 或通知表。
- 如字段不足，补充迁移脚本，至少需要支持：接收人、消息类型、标题、内容、已读状态、创建时间、业务关联信息。

### Infrastructure

- 第一版只做站内消息，不接入微信模板消息、短信、RocketMQ 异步投递或运营模板后台。
