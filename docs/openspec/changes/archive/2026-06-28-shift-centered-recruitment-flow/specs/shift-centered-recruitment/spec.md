## ADDED Requirements

### Requirement: 招聘计划与班次中心
系统须将企业招聘流程调整为“招聘计划 + 班次中心”的产品心智：岗位/职位作为可复用的招聘计划承载岗位信息，班次作为实际招聘和运营单元，承载报名、排班、考勤和结算。

#### Scenario: 企业进入招聘中心
- **WHEN** 企业用户登录并进入招聘/用工模块
- **THEN** 系统须展示招聘概览，包含今日班次、待审核报名、异常考勤和待结算薪资四个核心指标，并提供招聘计划、班次管理、报名审核、考勤确认和薪资结算入口

#### Scenario: 从班次进入报名审核
- **WHEN** 企业用户在班次管理中点击某个班次的报名人数
- **THEN** 系统须打开该班次的报名人列表，并支持按全部、待审核、已通过、已拒绝筛选

#### Scenario: 从班次进入考勤确认
- **WHEN** 企业用户在班次管理中查看某个班次详情
- **THEN** 系统须展示该班次的已排班人数、异常考勤数、待确认数和结算概览

### Requirement: 招聘计划与班次创建流程
系统须支持企业先创建或维护招聘计划（岗位信息、薪资、地点、联系人），再创建或批量创建班次（日期、时间、人数），并将岗位联系人和薪资规则同步到班次。

#### Scenario: 创建招聘计划并生成班次
- **WHEN** 企业用户创建或编辑招聘计划并提交班次信息
- **THEN** 系统须将岗位的联系人和薪资规则作为默认值同步到每个班次

#### Scenario: 班次修改仅影响后续报名
- **WHEN** 企业用户修改未开始班次的时间、人数或联系人
- **THEN** 系统须保存新的班次信息，并保留历史报名和已排班记录不变

### Requirement: 移动端班次工作台
企业小程序须以今日班次和待办为核心，提供班次列表、报名人抽屉、更多操作（编辑/复制/取消）和批量创建入口。

#### Scenario: 小程序首页展示招聘待办
- **WHEN** 企业用户进入小程序首页
- **THEN** 系统须展示今日新增报名、今日班次、待审核和异常考勤等核心数字

#### Scenario: 小程序班次管理列表
- **WHEN** 企业用户进入班次管理
- **THEN** 系统须展示带有状态标签、报名进度和指标的班次卡片，并支持按状态和日期筛选

### Requirement: 工人端班次语义统一
工人端岗位详情、报名确认、报名成功、我的排班和打卡相关页面须明确“报名班次、上岗班次”的表达，避免与岗位概念混淆。

#### Scenario: 报名确认展示班次信息
- **WHEN** 工人在报名确认页查看所选班次
- **THEN** 系统须展示班次日期、时间、地点和联系人，并明确表示“报名所选班次”

#### Scenario: 报名成功返回职位详情
- **WHEN** 工人提交报名并进入报名成功页
- **THEN** 系统须展示报名成功状态，并提供返回职位详情的按钮

### Requirement: 产品文档与官网表达统一
README、系统概述、技术规范和官网文案须统一为“招聘计划 + 班次中心”的流程描述，避免与实际班次报名业务冲突。

#### Scenario: README 产品描述
- **WHEN** 用户查看 README 的产品介绍
- **THEN** 系统须使用班次中心招聘流程表述，说明企业创建招聘计划、发布班次、工人报名、企业审核、考勤和结算

#### Scenario: 官网首页流程
- **WHEN** 用户访问官网首页查看产品流程
- **THEN** 系统须展示围绕班次的招聘运营闭环，并对应调整痛点、功能能力和 CTA 文案
