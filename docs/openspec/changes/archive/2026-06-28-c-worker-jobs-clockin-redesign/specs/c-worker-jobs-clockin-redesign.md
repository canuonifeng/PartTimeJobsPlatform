## 需求：找活列表页视觉与交互升级

系统须升级工人端找活列表页的视觉和交互，提升信息浏览效率和报名转化率。

### 场景：渐变头部展示问候与搜索
- **当** 工人进入找活列表页
- **则** 页面顶部展示绿色渐变头部，包含问候语（根据时间变化）、头像入口、搜索框
- **且** 搜索框支持关键词搜索职位、公司、地点

### 场景：分类筛选胶囊
- **当** 工人浏览找活列表
- **则** 搜索框下方展示横向滚动的分类胶囊标签
- **且** 选中态为绿色渐变背景 + 白字 + 阴影
- **且** 点击分类标签即时筛选对应类别的职位

### 场景：职位卡片信息重组
- **当** 工人浏览职位列表
- **则** 每张职位卡片左侧显示 4rpx 渐变色条
- **且** 卡片顶部左侧为大字薪资（渐变色文字，52rpx / 800 字重），右侧为热度标签（急招/热招/新上）
- **且** 薪资下方为职位标题
- **且** 标题下方为地点、距离、时间三项元信息
- **且** 元信息下方为福利标签行（包吃/包住/日结/无需经验等）
- **且** 卡片底部为企业信息行（Logo + 企业名）和报名人数（如"56人已报名"）

### 场景：下拉刷新与上拉加载
- **当** 工人下拉列表
- **则** 触发刷新，重新加载第一页
- **当** 工人滚动到列表底部
- **则** 自动加载下一页数据

### 场景：点击卡片进入详情
- **当** 工人点击某张职位卡片
- **则** 跳转到职位详情页

## 需求：职位详情页与报名流程优化

系统须优化职位详情页的信息组织和报名交互，减少报名步骤。

### 场景：班次选择前置
- **当** 工人进入职位详情页
- **则** 第一个卡片即为"选择班次报名"区域
- **且** 班次区顶部有日期快速筛选胶囊（今天/明天/周六/周日/下周一等）
- **且** 班次以网格卡片形式展示，每张卡片显示日期、时间段、薪资、状态

### 场景：班次卡片多选
- **当** 工人点击可选班次卡片
- **则** 该卡片变为选中态（绿色边框 + 浅绿背景 + "已选"角标）
- **当** 工人再次点击已选班次卡片
- **则** 取消选中，恢复可选状态
- **当** 班次已报满
- **则** 卡片显示"已报满"角标且置灰，不可点击

### 场景：已选班次实时汇总
- **当** 工人选择或取消班次
- **则** 班次区底部汇总条实时更新"已选 N 个班次 · 合计 ¥XXX"

### 场景：底部固定操作栏
- **当** 工人浏览详情页
- **则** 页面底部固定显示操作栏，左侧为收藏按钮，右侧为报名按钮
- **且** 未选班次时报名按钮显示"请先选择班次"且置灰不可点击
- **且** 已选 N 个班次时报名按钮显示"立即报名（N班）"且为绿色渐变可点击

### 场景：底部弹窗确认报名
- **当** 工人点击"立即报名"按钮
- **则** 从底部弹出半屏确认抽屉，展示职位名、已选班次明细、合计金额、一条信用提醒
- **且** 抽屉底部有"取消"和"确认报名"两个按钮

### 场景：确认报名成功
- **当** 工人在确认抽屉中点击"确认报名"
- **则** 按钮进入 loading 状态，调用报名接口
- **且** 成功后显示全屏成功弹层（绿色渐变 + 图标弹跳动效 + "报名成功" + 引导文案）
- **且** 成功弹层有"查看我的排班"和"继续找活"两个按钮

### 场景：报名失败
- **当** 报名接口返回错误
- **则** 显示 Toast 提示错误信息，抽屉保持打开状态

## 需求：打卡页仪表盘式升级

系统须将打卡首页升级为仪表盘式布局，突出当前班次和打卡操作。

### 场景：渐变头部与问候
- **当** 工人进入打卡 Tab
- **则** 顶部展示绿色渐变头部，包含问候语、今日班次概览、消息入口（带未读红点）

### 场景：当前班次毛玻璃卡片
- **当** 工人有今日班次
- **则** 渐变头部内展示当前/下一班次的毛玻璃卡片，包含工作时间、岗位名称、工作地点+距离

### 场景：超大圆形打卡按钮
- **当** 工人进入打卡页且有待操作的班次
- **则** 页面中央展示超大圆形打卡按钮（直径约 400rpx）
- **且** 按钮带呼吸脉冲动效
- **且** 按钮中央显示当前操作主文字（签到/签退/已完成）
- **且** 按钮显示距离上班的剩余时间和当前距离工作地点距离

### 场景：打卡按钮状态变化
- **当** 班次处于不同状态
- **则** 打卡按钮呈现不同外观：
  - 待签到（提前）：绿色渐变 + "签到" + 剩余时间 + 距离
  - 待签到（已到时间）：绿色渐变 + 脉冲加强 + "立即签到"
  - 工作中：蓝色渐变 + "签退" + 已工作时长
  - 已完成：浅绿 + "已完成 ✓" + 今日工时
  - 位置异常：红色渐变 + "无法签到" + 距离过远提示
  - 迟到：橙色渐变 + "迟到签到" + 已迟到时长

### 场景：状态提示条
- **当** 工人在打卡页
- **则** 打卡按钮下方显示三个状态提示：位置正常/异常、网络状态、提前/准时/迟到

### 场景：今日班次列表
- **当** 工人查看打卡页下半部分
- **则** 显示今日班次卡片列表
- **且** 当前/待上岗班次左侧有绿色指示条高亮
- **且** 已完成班次灰显
- **且** 每条显示时间、岗位名、地点、状态标签
- **且** 右上角有"全部排班 →"入口

### 场景：打卡记录入口
- **当** 工人想看历史记录
- **则** 今日班次卡片下方有"打卡记录"入口行，点击跳转打卡记录页

### 场景：签到/签退成功反馈
- **当** 工人点击打卡按钮且操作成功
- **则** 显示全屏成功遮罩 + ✓ 弹跳动画 + 操作时间 + 工时信息
- **且** 1.5 秒后自动关闭，按钮状态切换

系统须将独立的打卡记录页调整为纯历史记录展示。

### 场景：月度统计概览
- **当** 工人进入打卡记录页

## 需求：全局视觉规范统一

系统须统一 C 端工人小程序的视觉规范。

### 场景：色彩系统
- **给定** 设计规范中的色彩定义
- **则** 所有页面使用统一的主色、辅助色、文字色、背景色体系

### 场景：圆角与阴影
- **则** 卡片统一 16rpx 圆角
- **且** 按钮统一 24rpx 圆角（胶囊形）
- **且** 标签统一 20rpx 圆角
- **且** 卡片统一使用柔和阴影

### 场景：字体层级
- **则** 所有页面遵循统一的字体大小和字重层级规范
