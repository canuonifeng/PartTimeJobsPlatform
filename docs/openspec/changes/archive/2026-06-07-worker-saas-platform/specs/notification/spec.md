## 新增需求

### 需求：系统支持多种通知渠道
系统须支持站内通知、微信模板消息（小程序）和短信通知。

#### 场景：发送站内通知
- **当** 触发事件发生（收到报名、排班指派、工资确认）
- **则** 系统须为目标用户创建站内通知

#### 场景：发送微信模板消息
- **当** 触发事件发生且用户有微信会话
- **则** 系统须通过小程序发送微信模板消息

### 需求：通知模板可配置
系统须允许运营人员管理每种事件类型和渠道的通知模板。

#### 场景：更新通知模板
- **当** 运营人员编辑通知模板
- **则** 系统须对后续通知使用更新后的模板

### 需求：通知投递日志须记录
系统须记录所有通知的投递状态和错误信息。

#### 场景：查看投递日志
- **当** 运营人员或企业用户查看某事件的通知记录
- **则** 系统须展示每个渠道的投递状态

### 需求：兼职接收关键事件通知
系统须在以下事件通知兼职：报名状态变更、排班指派、签到提醒、工资确认、岗位推荐。

#### 场景：录用通知
- **当** 企业录用兼职的报名
- **则** 系统须发送通知给兼职

#### 场景：排班提醒
- **当** 排班开始时间距当前不足N小时
- **则** 系统须向被指派的兼职发送提醒通知

### 需求：企业接收关键事件通知
系统须在以下事件通知企业：收到新报名、兼职签到/签退、考勤异常、工资确认。

#### 场景：新报名通知
- **当** 兼职报名某岗位
- **则** 系统须发送通知给该岗位所属企业
