# Enterprise Job Module Refinement 规格

## 需求

### REQ-1: 标注职位列表展示标注特有信息
**优先级**: P0

**描述**: 企业端"标注任务"列表（AnnotationJobList）展示标注业务特有字段，不再混用零工字段。

**场景**:
- 场景 1：企业进入"标注任务"模块 → 列表列包含：职位名称、薪资标准、任务总量、批次代号、状态、操作（编辑/发布/下线/删除/批次管理）。
- 场景 2：列表不显示零工特有列（工作地点、招聘人数、报名情况）。

**约束**:
- 列表数据来源为现有 `GET /api/enterprise/jobs?taskType=ANNOTATION`（listJobs），字段在 JobVO 中补齐（任务总量 totalItems、薪资标准由 rates 展示、批次代号 batchCode）。
- 批次代号取该职位批次（job_schedules）中最近/最新一条的 batch_code，无批次时显示"-"。
- 薪资标准展示取薪资规则首档（如"时薪 ¥30起"），多档时列表仅显示首档并带"起"字，详情可看全。

**验收标准**:
- [ ] 标注列表列集合符合上述场景。
- [ ] 无批次时批次代号列显示占位符，不报错。

### REQ-2: 标注职位表单按标注业务渲染
**优先级**: P0

**描述**: 创建/编辑标注职位时，表单只显示标注相关区块，隐藏模版选择、地址、单价、排班等不适用的零工/旧字段。

**场景**:
- 场景 1：新建标注职位（taskType=ANNOTATION）→ 表单显示：职位名称、标注职位类型、招聘人数、截止日期、职位图片、薪资标准（时薪/日薪/按单，可多档）、任务总量、岗位职责、任职要求、联系人、联系方式、岗位标签、急招、状态。
- 场景 2：编辑标注职位 → 同样只显示上述字段。
- 场景 3：新建/编辑零工职位（taskType=WORK）→ 表单显示现状全部区块（模版选择、职位类型、招聘人数、截止日期、地址、图片、薪资、排班等），行为不变。

**约束**:
- 标注职位类型独立：图像标注 / 语音标注 / 文本标注 / 视频标注 / 混合数据标注（与零工共享分类不同）。
- 标注时隐藏：职位模版选择、地址信息（省/市/区/详细地址/坐标/工作地点选择）、单价、排班时段。
- 标注时保留：职位名称、标注职位类型、招聘人数、截止日期、职位图片、薪资标准、任务总量、岗位职责、任职要求、联系人、联系方式、岗位标签、急招、状态。
- 提交 payload：标注时地址字段（location/province/city/district/address/latitude/longitude）与排班（schedules）不参与提交（null/空）；招聘人数/截止日期/图片正常提交；薪资标准以 rates 提交。
- 后端校验调整：taskType=ANNOTATION 时校验 rates 至少一条 与 totalItems>0，不再强制 pricingMode/pricePerUnit。

**验收标准**:
- [ ] 标注表单无模版选择/地址/单价/排班。
- [ ] 标注表单保留招聘人数/截止日期/职位图片。
- [ ] 标注职位类型五项可选。
- [ ] 标注表单可正常创建/编辑并提交（后端校验通过，不报计价模式缺失）。
- [ ] 零工表单与现状一致。

### REQ-3: 零工模块无回归
**优先级**: P1

**描述**: 零工招聘列表与表单保持现状。

**场景**:
- 场景 1：零工列表字段、筛选、操作（邀请/编辑/发布/关闭/重开）不变。
- 场景 2：零工表单全部区块不变。

**验收标准**:
- [ ] 零工模块行为与改造前一致。
- [ ] enterprise-pc `npm run build` 通过。
