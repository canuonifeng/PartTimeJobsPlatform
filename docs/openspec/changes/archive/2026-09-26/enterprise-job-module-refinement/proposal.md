# Proposal: enterprise-job-module-refinement

## 背景与问题

零工职位（WORK）与标注任务（ANNOTATION）是本质不同的两类业务：

- **零工**：按"人头×时段"（招聘人数、时薪/日薪/按单薪资标准、排班时段），走报名→排班→考勤→手动结算。
- **标注**：按"任务总量×薪资标准"（任务总量 + 时薪/日薪/按单），发布后维护批次，走抢单→任务单→外部回调→自动结算。

但企业端 PC 后台目前**两个模块的界面高度雷同**：

1. **列表页**：`AnnotationJobList.vue` 沿用了零工 `JobList.vue` 的字段（工作地点、招聘人数、报名情况），未展示标注特有信息（任务总量、批次），仅多一个"批次管理"按钮。
2. **创建/编辑表单**：`JobForm.vue` 是共用表单，标注类型显示"计价方式/单价"，但同时显示零工的招聘人数、截止日期、地址信息、职位图片、薪资标准、排班时段等零工区块；且标注职位不需要选择职位模版、应有独立职位类型。

这导致企业用户看到的两个模块"一样"，无法体现两类职位的业务差异。

## 变更目标

让企业端后台的零工模块与标注模块在**列表字段、表单区块**上真正区分开，各展示各自业务特有的信息。标注模块按用户确认的口径收敛表单与列表。

## 范围

- 包含：
  - 标注职位列表（`AnnotationJobList.vue`）：移除零工列（工作地点/招聘人数/报名情况），改为展示标注特有列：职位名称、薪资标准、任务总量、批次代号、状态、操作。
  - 标注职位创建/编辑表单（`JobForm.vue` 按 taskType 条件渲染）：
    - **不需要**选择职位模版；
    - 职位类型用**标注独立类型**：图像标注 / 语音标注 / 文本标注 / 视频标注 / 混合数据标注；
    - **不需要**地址信息（省/市/区/详细地址/坐标/工作地点选择均隐藏）；
    - **不需要单独的"单价"字段**，报酬用**薪资标准**（时薪/日薪/按单，复用零工薪资区块，可多档）；
    - **不需要**排班时段；
    - 保留：职位名称、标注职位类型、招聘人数、截止日期、职位图片、薪资标准、任务总量、岗位职责、任职要求、联系人、联系方式、岗位标签、急招、状态。
  - 后端配套：
    - 标注创建/更新校验调整：不再强制 pricingMode/pricePerUnit，改为校验薪资标准（rates 至少一条）与任务总量（totalItems>0）；
    - 标注职位类型独立（前端独立选项 + 后端 categoryName 兼容）。
  - 零工模块（`JobList.vue` 及表单零工分支）保持不变。
- 不包含（非目标）：
  - 不改 C 端（worker-uniapp）相关页面。
  - 不改零工列表/表单的现有字段与交互。
  - 不改标注自动结算的金额计算口径（按薪资标准×完成量，若结算依赖 pricePerUnit 需另行评估——见风险）。
  - 不做界面美化/组件抽取重构。

## 验收标准

- [ ] 企业端"标注任务"列表不显示工作地点/招聘人数/报名情况列；显示任务总量、批次代号（有批次时）。
- [ ] 标注职位创建/编辑表单：无模版选择、无地址信息、无单价、无排班时段。
- [ ] 标注表单保留：招聘人数、截止日期、职位图片。
- [ ] 标注职位类型独立可选：图像标注/语音标注/文本标注/视频标注/混合数据标注。
- [ ] 标注表单薪资标准可填（时薪/日薪/按单，多档），任务总量必填。
- [ ] 标注职位创建/编辑保存成功（后端校验通过）。
- [ ] 零工模块列表与表单与现状一致，无回归。
- [ ] enterprise-pc `npm run build` 通过。

## 风险与开放问题

- 风险：标注结算若依赖 `pricePerUnit` 按件计算，本 change 只改表单与校验（前端不再传单价），**自动结算口径需另行确认**；若按薪资标准（如按单）结算，结算逻辑不在本 change 范围。
- 风险：标注历史数据中已填写的地址/单价字段保留在库中，仅前端不再展示。
- 决策（已确认）：
  - 标注职位类型沿用 `categoryId` 字段，独立值域 101–105。
  - 列表薪资标准展示首档，多档时格式如"时薪 ¥30起"。
- 待确认：无。
