## 新增需求

### 需求：系统根据考勤和薪资规则自动计算工资
系统须根据打卡数据和岗位配置的薪资规则自动计算兼职工资。

#### 场景：按时薪计算工资
- **当** 薪资结算批次运行时处理按时计薪的排班岗位
- **则** 系统须将打卡总工时乘以时薪单价

#### 场景：按日薪计算工资
- **当** 薪资结算批次运行时处理按日计薪的岗位
- **则** 系统须将出勤天数乘以日薪单价

### 需求：企业可审核和确认薪资批次
系统须允许企业用户查看计算后的工资、进行调整并确认薪资批次。

#### 场景：确认薪资批次
- **当** 企业用户审核后点击"确认"薪资批次
- **则** 系统须将该批次标记为已确认并通知兼职

#### 场景：调整单个兼职工资
- **当** 企业用户在薪资批次中调整某位兼职的工资
- **则** 系统须记录调整原因并重新计算批次总额

### 需求：兼职可查看历史收入
系统须允许兼职查看收入明细、发薪记录和当前余额。

#### 场景：查看收入明细
- **当** 兼职打开收入页面
- **则** 系统须展示每份岗位的收入、状态（待结算/已确认/已发放）和总余额

### 需求：兼职可提现收入
系统须允许兼职将可用余额提现至微信支付、支付宝或银行卡。

#### 场景：提现成功
- **当** 兼职发起提现且可用余额和收款账户均有效
- **则** 系统须处理提现并更新余额

#### 场景：余额不足无法提现
- **当** 兼职发起的提现金额超过可用余额
- **则** 系统须拒绝请求并提示余额不足

### 需求：企业可批量发放工资
系统须允许企业财务用户对已确认的工资进行批量发放。

#### 场景：批量发放工资
- **当** 企业财务用户确认并提交一个发放批次
- **则** 系统须发起对批次内所有兼职的支付
