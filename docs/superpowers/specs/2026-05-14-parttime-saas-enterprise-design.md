# 兼职SaaS平台 — 企业端设计文档

> 本文档覆盖企业后台管理系统的架构、领域模型、工作流和技术选型。C 端（兼职小程序）和平台管理端将在后续迭代中设计。

## 技术栈

| 层次 | 选型 |
|------|------|
| 后端框架 | Spring Boot |
| 数据库 | MySQL |
| ORM | MyBatis |
| 缓存 | Redis |
| 消息队列 | RocketMQ |
| 定时调度 | XXL-Job |
| PC 管理端 | Vue 3 + Element Plus |
| 小程序端 | UniApp（Vue 语法，一套代码出微信小程序 + H5） |

## 架构方案：模块化单体

一个后端应用，内部按领域拆分为 6 个独立模块。模块间通过 `interface` 调用，严禁直接访问对方数据库。

```
┌──────────────────────────────────────────────────┐
│                  API 网关层                       │
│     PC管理端 REST · 小程序端 REST                 │
├──────────────────────────────────────────────────┤
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐  │
│  │ 岗位  │ │ 排班  │ │ 结算  │ │ 人员  │ │ 企业  │  │
│  │ 模块  │ │ 模块  │ │ 模块  │ │ 模块  │ │ 模块  │  │
│  └──┬───┘ └──┬───┘ └──┬───┘ └──┬───┘ └──┬───┘  │
│     └────────┴────────┴────────┴────────┘        │
│                   共享内核                         │
│         认证鉴权 · 通知 · 存储 · 位置 · 支付       │
├──────────────────────────────────────────────────┤
│                    MySQL · Redis                  │
└──────────────────────────────────────────────────┘
```

## 模块职责

### 岗位模块
岗位 CRUD、分类管理、搜索筛选、上下架、薪资规则配置。PC 管理端和小程序企业端共用。

核心实体：
- **Job** — title, description, location, status (draft/published/closed/expired), company_id, category_id, headcount, deadline
- **JobRate** — job_id, type (hourly/daily/piecework), amount, currency, rules (JSON，支持混合模式)
- **JobSchedule** — job_id, date, start_time, end_time, slots_available（非必填，仅排班型岗位使用）
- **JobApplication** — job_id, worker_id, status (pending/accepted/rejected), applied_at
- **JobCategory** — name, parent_id, sort_order（多级分类树）

### 排班模块
排班模板管理、班次定义、人员指派、考勤统计。PC 管理端为主。

### 结算模块
薪资规则计算、工时/工单汇总、发薪记录、财务报表。PC 管理端 + 小程序。

### 人员模块
兼职人员资料管理、应聘记录、黑名单、评价。PC 管理端 + 小程序。

### 企业模块
企业资料、内部成员管理（HR/主管/财务）、资质认证、账单。

### 共享内核
统一认证鉴权、消息通知、文件存储、位置服务、支付网关。三端共用。

## 角色权限

企业内设 4 个角色：

| 角色 | 权限范围 |
|------|----------|
| 管理员 | 全部权限，含成员管理、企业设置 |
| HR | 岗位发布、人员管理、面试筛选 |
| 主管 | 排班管理、考勤确认 |
| 财务 | 薪资核算、发薪操作 |

## 岗位发布工作流

```
草稿 → 填写基本信息 → 配置薪资规则 → [可选] 配置排班 → 预览 → 发布（直接上架）
```

发布后状态机：
```
draft → published → closed → reopened
               ↘ expired (deadline到达自动)
```

## 关键约定

1. **模块间通信**：通过 interface 调用，不要跨模块访问数据库。
2. **混合薪资**：一个 Job 挂多条 JobRate，C 端按岗位展示时清晰列出各项薪资规则。
3. **岗位状态**：所有状态变更记录操作日志，便于追溯。
4. **直接发布**：岗位无需平台审核即上架。平台审核机制独立设计在平台管理端。
