# 企业端小程序全量页面 UI 优化设计

## 背景

企业端小程序已完成首页、报名管理、排班考勤等关键页面的局部优化。本次继续对报名管理和排班考勤之外的所有页面做一次全量布局、排版和交互统一，目标是让企业端小程序形成一致的视觉语言，减少页面之间的割裂感，并提升移动端可读性和操作效率。

## 范围

本次采用 C 方案：企业小程序端全量页面一次性优化。所有改动只发生在 `enterprise-uniapp`，不修改后端、PC 端、工人端小程序或平台端小程序。

纳入范围：

- 职位管理列表、职位详情、职位表单。
- 薪资管理。
- 兼职管理。
- 账号管理。
- 工作地点列表、工作地点表单。
- 职位模板列表、职位模板表单。
- 企业资金。
- 企业设置。
- 企业实名认证。
- 相关弹窗、空状态、加载状态和底部操作区。

不纳入范围：

- 报名管理页面。
- 排班考勤页面。
- 后端接口和业务规则。
- 企业 PC、平台 PC、工人端小程序、平台端小程序。
- 路由结构、权限逻辑、数据字段含义。

## 设计目标

1. 统一页面骨架：页面背景、头部、内容容器、卡片间距保持一致。
2. 统一卡片风格：圆角、阴影、标题区、状态标签、信息块和操作按钮形成固定模式。
3. 统一表单体验：字段分组、输入框、选择器、提交按钮和底部安全间距一致。
4. 统一交互反馈：加载、空状态、禁用、提交中、危险操作确认保持一致。
5. 不改变业务流程：只优化展示和交互，不新增接口，不改变现有数据提交格式。

## 视觉规范

### 页面背景

- 使用浅灰绿色背景：`#f6f8f7`。
- 页面内容区使用 `padding: 24rpx 28rpx 40rpx` 作为基础间距。
- 避免使用负 margin 制造重叠，防止不同机型下内容遮挡。

### 头部

- 列表、详情、资金、设置、认证等页面优先使用绿色渐变头部。
- 渐变参考：`#18c86b → #08a95a → #078a49`。
- 头部只承担页面标题、说明、核心统计或主要入口，不放过多操作。
- 高度根据内容自适应，避免遮挡首屏卡片。

### 卡片

- 卡片背景使用白色。
- 圆角统一为 `24rpx`。
- 阴影参考：`0 12rpx 34rpx rgba(23,83,53,0.08)`。
- 卡片之间保持 `20rpx` 到 `24rpx` 间距。
- 长文本必须限制宽度，使用 `min-width: 0`、省略号或换行策略，避免撑宽页面。

### 标签与信息块

- 状态使用胶囊标签，颜色按语义区分：成功绿色、警告橙色、禁用灰色、危险红色。
- 高频信息用浅底胶囊或信息行展示，减少密集文本。
- 金额、人数、状态、时间等核心数据应突出显示。

### 按钮

- 主按钮使用绿色渐变或企业绿色。
- 次按钮使用浅色边框或浅色背景。
- 危险按钮使用红色语义，并保留确认弹窗。
- 同一卡片内操作不超过三项；超过三项时使用“更多”或分组排布。

## 页面设计

### 职位管理

职位列表沿用卡片化列表结构，优化标题、状态和操作区：

- 卡片顶部展示职位名称和状态标签。
- 中部用信息胶囊展示薪资、人数、报名数、工作地点。
- 底部固定展示主要操作，如报名记录、排班、编辑、下架或删除。
- 搜索、筛选或新增入口保持在顶部区域，减少滚动后迷失。

职位详情使用分组信息卡：

- 基本信息、工作要求、薪资规则、时间地点分区展示。
- 详情底部放置固定操作区，避免主要操作被长内容淹没。

职位表单使用分组表单：

- 基础信息、薪资人数、工作时间、地点要求拆成多个卡片区块。
- 输入框、选择器、文本域高度和间距统一。
- 底部提交按钮固定或接近底部，并保留安全距离。

### 薪资管理

薪资管理强调统计和批量操作：

- 顶部展示核心统计，如待结算人数、总工时、预计金额。
- 列表卡片展示工人姓名、岗位、工时、金额、结算状态。
- 已结算、待结算、异常状态使用不同标签。
- 空状态提示当前筛选下无薪资记录，并提供返回或刷新操作。

### 兼职管理

兼职管理以人员信息可读性为主：

- 卡片顶部展示姓名、性别、年龄、手机号。
- 中部展示报名岗位、最近工作、状态等信息。
- 操作区保留查看、联系、移除或其他已有操作。
- 手机号等长文本不得撑宽卡片。

### 账号管理

账号管理以权限和状态清晰为主：

- 顶部展示账号数量或新增账号入口。
- 卡片展示账号姓名、手机号、角色、启用状态。
- 启用/禁用、编辑、删除等操作语义明确。
- 删除保留确认弹窗。

### 工作地点

地点列表使用地址卡片：

- 顶部展示地点名称和默认/启用状态。
- 中部展示详细地址、联系人、联系电话。
- 底部展示编辑、设为默认、删除等操作。

地点表单统一为卡片式表单：

- 地址、联系人、电话、定位等字段分组。
- 若已有地图或定位入口，仅优化按钮和间距，不改变能力。

### 职位模板

模板列表用于快速复用：

- 卡片顶部展示模板名称和启用状态。
- 中部展示岗位类型、薪资、工作时间等摘要。
- 底部展示使用模板、编辑、删除。

模板表单与职位表单保持相同分组和控件样式。

### 企业资金

企业资金页面强调账户余额和流水：

- 顶部使用余额卡突出当前可用余额。
- 次级统计展示冻结金额、充值/支出等现有字段。
- 流水记录使用时间线或卡片结构展示金额、类型、时间、状态。
- 金额正负使用颜色区分。

### 企业设置

企业设置以分组菜单为主：

- 企业信息、认证信息、账号安全、系统设置分组展示。
- 每个菜单项使用统一高度、图标区、标题、说明和右箭头。
- 高风险操作使用危险色并二次确认。

### 企业实名认证

实名认证页保留现有流程，优化步骤感和材料展示：

- 顶部展示认证状态和说明。
- 表单字段分组，上传区域统一卡片样式。
- 提交按钮展示提交中状态，避免重复提交。
- 审核中、已通过、被驳回分别展示清晰提示。

## 交互设计

### 加载状态

- 页面首次加载使用现有 loading 能力，布局上避免内容跳动。
- 提交类按钮在请求中展示禁用状态和提交中提示。

### 空状态

- 列表为空时使用统一空状态：简短说明 + 可选主操作。
- 空状态不占用过高空间，保证页面视觉平衡。

### 弹窗

- 删除、禁用、下架等破坏性操作必须保留确认弹窗。
- 弹窗文案清楚说明结果。

### 滚动

- 优先使用页面级滚动。
- 避免无必要的嵌套 `scroll-view`。
- 表单和详情页底部保留安全间距，防止按钮被系统区域遮挡。

## 技术方案

- 只修改 `enterprise-uniapp/src/pages` 下相关页面的模板、样式和少量交互状态。
- 不调整 API 封装，不新增后端接口。
- 如发现多个页面重复样式明显，可在当前页面内先统一类名；是否抽取公共样式以最小改动为原则。
- 保持 UniApp 和微信小程序兼容，避免使用 H5 专属 CSS 或浏览器 API。
- 所有长文本容器必须处理溢出，避免再次出现卡片右侧超屏。

## 验证

完成后执行：

```bash
cd enterprise-uniapp && npm run build:mp-weixin
```

同时检查：

- 职位、薪资、兼职、账号、地点、模板、资金、设置、认证页面能正常构建。
- 页面无明显横向溢出。
- 表单提交、删除确认、启用禁用等既有交互仍可触发。
- `dist/` 构建产物不提交。
