# 企业端小程序运营中台重构设计

## 背景

企业端小程序当前功能覆盖较完整，已包含职位、报名、排班、考勤、薪资、地点、模板、兼职、账号、余额、设置和认证等页面。但整体体验仍偏“首页菜单集合 + 二级业务页面”，用户需要先理解模块位置，再进入具体任务处理。对于企业招聘运营场景，更高频的问题是：当前招聘进展如何、哪里需要处理、下一步该做什么。

本次重设计将企业端小程序从“功能菜单型管理端”升级为“招聘运营工具”。设计重点不是单纯美化页面，而是围绕企业从发布职位到薪资结算的完整链路，重组信息架构、首页表达、底部导航、流程页、待办页、列表卡片和表单体验。

## 范围

本次采用“运营中台重构”方案，对 `enterprise-uniapp` 做全量重设计。

纳入范围：

- 首页从功能宫格重构为综合运营工作台。
- 新增或重组底部导航：工作台、流程、待办、我的。
- 重组页面入口和功能分组。
- 重设计职位、报名、排班、考勤、薪资等核心流程页面。
- 重设计地点、模板、兼职、账号、余额、企业设置、实名认证、登录等支撑页面。
- 统一视觉风格、卡片、标签、按钮、表单、空状态、加载状态和底部操作区。
- 优化发布职位表单，支持模板快速发布和分步骤新建职位。

不纳入范围：

- 不修改后端业务规则。
- 不新增必须依赖后端开发的新业务能力。
- 不修改企业 PC、平台 PC、工人端小程序或平台端后端。
- 不提交 `dist/` 等构建产物。

## 设计目标

1. 将产品气质明确为“招聘运营工具”，突出职位发布、报名审核、排班考勤和薪资结算链路。
2. 首页承担运营总览能力，一屏内展示核心数据、流程进度、今日待办和快捷动作。
3. 用底部 Tab 建立稳定导航，让高频任务不再依赖首页宫格查找。
4. 用流程时间线表达招聘运营主线，让用户知道每一步的状态、数量和入口。
5. 用按业务类型分组的待办页承接日常处理任务，提高操作效率。
6. 统一全端视觉语言，延续绿色品牌识别，同时提升现代感、专业感和移动端可读性。
7. 控制信息密度为中密度，保证一屏有足够信息，又不牺牲点击和阅读体验。

## 产品结构

### 底部导航

新版底部导航采用四个 Tab：

| Tab | 定位 | 主要内容 |
|---|---|---|
| 工作台 | 综合运营首页 | 核心数据、招聘流程、今日待办、快捷动作 |
| 流程 | 招聘链路推进 | 发布、报名、审核、排班、考勤、薪资流程时间线 |
| 待办 | 高频任务处理 | 报名、排班、考勤、薪资待处理事项 |
| 我的 | 企业与基础管理 | 企业资料、地点、模板、兼职、账号、余额、设置、认证、退出登录 |

### 功能分组

当前首页中的功能入口调整如下：

- 职位管理：进入“流程”，同时保留工作台快捷发布入口。
- 报名管理：进入“流程”和“待办”的报名分组。
- 排班考勤：拆分为流程中的排班、考勤节点，并在待办中展示待排班和异常考勤。
- 薪资管理：进入流程中的薪资节点，并在待办中展示待结算事项。
- 工作地点、职位模板、兼职管理、账号管理、企业设置、账户余额、实名认证：统一放入“我的”。

## 页面设计

### 工作台

工作台采用综合运营型首页，结构从上到下为：

1. 企业问候区：展示企业名称、当前登录人、简短状态提示。
2. 运营数据概览：展示发布中职位、总报名数、待处理数、今日排班或待结算数。
3. 招聘流程概览：用横向流程或卡片链路展示发布、报名、审核、排班、考勤、薪资的当前状态。
4. 今日待办：展示报名、排班、考勤、薪资中最需要处理的事项。
5. 快捷动作：发布职位、处理报名、创建排班、处理薪资等主操作。
6. 常用入口：根据用户高频行为展示最近访问或常用功能。

工作台不再作为完整功能宫格，而是作为运营入口。低频配置类功能移入“我的”。

### 流程

流程页采用流程时间线结构，围绕企业招聘运营主线组织：

```text
发布职位 → 收到报名 → 审核报名 → 创建排班 → 考勤确认 → 薪资结算
```

每个流程节点展示：

- 节点名称。
- 当前数量或状态，如发布中职位数、待审核报名数、待排班人数。
- 异常提示，如班次未满员、考勤异常、薪资待确认。
- 主入口按钮，如去发布、去审核、去排班、去结算。

流程页用于帮助企业判断招聘进度卡点，而不是替代所有列表页。点击节点后进入对应列表或处理页面。

### 待办

待办页按业务类型分组：

- 报名：待审核、待联系、待确认的报名记录。
- 排班：未排班、班次未满员、需要调整的班次。
- 考勤：缺卡、迟到早退、工时异常、待确认记录。
- 薪资：待结算、结算中、结算失败或需重试记录。

每个分组展示数量、列表摘要和主操作。待办页强调处理效率，避免混合成单一长列表导致用户难以定位任务类型。

### 我的

我的页承接企业资料和基础管理：

- 企业信息和认证状态。
- 账户余额和资金入口。
- 工作地点。
- 职位模板。
- 兼职管理。
- 账号管理。
- 企业设置。
- 退出登录。

页面采用分组菜单，使用统一图标区、标题、说明和右箭头。高风险操作使用危险色并保留确认弹窗。

### 职位管理

职位列表采用中密度卡片：

- 顶部展示职位名称和状态标签。
- 中部展示薪资、人数、报名数、地点、工作时间等关键信息。
- 底部展示主要操作，如报名记录、编辑、发布、下架、邀请。
- 筛选保留全部、草稿、已发布、已关闭等状态。

职位详情分区展示基础信息、薪资规则、工作时间、工作地点、报名情况和操作区。

### 发布职位

发布职位采用混合式表单：

- 支持从模板快速发布：先选择职位模板，再补充日期、时间、地点、人数等变动信息。
- 支持分步骤新建职位：基础信息、薪资时间、地点要求、发布确认。
- 表单字段使用卡片分组，底部主按钮固定或接近底部安全区。
- 发布确认页集中展示关键字段，降低误发布风险。

### 报名管理

报名列表采用中密度卡片：

- 顶部展示工人姓名、报名状态和报名时间。
- 中部展示职位、手机号、年龄、经验或备注等关键信息。
- 底部展示通过、拒绝、联系、查看详情等操作。
- 处理成功后刷新当前分组和工作台待办数量。

### 排班考勤

排班页面突出班次状态：

- 按日期或职位展示班次。
- 卡片展示岗位、时间、地点、已排人数和缺口。
- 主操作为查看班次、添加人员、调整排班。

考勤页面突出异常和确认：

- 展示工人、岗位、班次、签到签退、工时、状态。
- 异常状态用警告色标签突出。
- 支持进入详情处理异常或确认工时。

### 薪资管理

薪资页面突出结算状态和金额：

- 顶部展示待结算人数、预计金额、已结算金额等统计。
- 列表展示工人、岗位、工时、应付金额、结算状态。
- 批量操作保持清晰选择态，防止误结算。
- 支付、删除等高风险操作保留确认弹窗。

### 基础管理页面

地点、模板、兼职、账号、余额、企业设置、实名认证统一使用新版页面骨架：

- 头部展示页面名称、说明和必要统计。
- 内容区使用白色卡片和浅色信息块。
- 操作按钮控制在每张卡片三项以内。
- 空状态提供说明和主操作。
- 表单页按字段含义分组，长文本和手机号等内容必须处理溢出。

## 视觉规范

### 风格

采用“清爽专业绿”：延续当前绿色品牌识别，但弱化重渐变堆叠，提升留白、层级和卡片质感。

### 色彩

- 主色：`#16a34a`。
- 深绿色：`#047857`。
- 浅绿色背景：`#f6f8f7`。
- 卡片白：`#ffffff`。
- 主文字：`#1f2933`。
- 次文字：`#64748b`。
- 弱文字：`#98a3b3`。
- 边框：`#edf0f3`。
- 警告：`#f59e0b`。
- 危险：`#ef4444`。
- 信息：`#3b82f6`。

### 组件

- 页面背景统一为浅灰绿色。
- 卡片圆角统一为 `24rpx`，重要运营卡片可使用 `28rpx`。
- 页面内容区基础间距使用 `24rpx 28rpx 40rpx`。
- 状态使用胶囊标签，颜色按语义区分。
- 主按钮使用绿色主色或轻渐变，次按钮使用浅色背景或边框。
- 列表卡片保持中密度，优先展示标题、状态、核心指标和主操作。
- 底部 Tab 使用清晰选中态，避免与页面内容争抢视觉焦点。

## 交互规范

### 导航

- 高频处理任务优先通过底部 Tab 进入。
- 工作台快捷操作只放高频入口，不承载全部功能。
- 低频配置统一放入“我的”。

### 列表

- 列表页保留当前筛选能力。
- 卡片点击进入详情，卡片底部按钮执行明确操作。
- 同一卡片内操作超过三项时使用“更多”或二级操作区。

### 表单

- 发布职位支持模板快速发布和分步骤新建。
- 长表单拆分步骤，当前步骤只展示必要字段。
- 提交中按钮禁用，避免重复提交。
- 发布、删除、结算等关键动作保留确认反馈。

### 状态

- 加载状态避免页面跳动。
- 空状态使用统一插画感容器或轻量图形，占位文案说明原因并提供主操作。
- 异常、失败、危险操作使用明确语义色和确认文案。

## 技术落地原则

- 改动集中在 `enterprise-uniapp`。
- 优先复用现有 API 和字段，不强依赖新增后端接口。
- 新增 TabBar 和页面入口时同步更新 `enterprise-uniapp/src/pages.json`。
- 若已有页面可承接新信息架构，优先重组入口和样式，不做无关重构。
- 保持 UniApp 和微信小程序兼容，避免 H5 专属 CSS、浏览器 API 和不兼容选择器。
- 不提交构建产物。

## 验证

实施完成后执行：

```bash
cd enterprise-uniapp && npm run build:mp-weixin
```

重点验证：

- 底部 Tab 可正常切换。
- 工作台、流程、待办、我的入口正确。
- 职位、报名、排班、考勤、薪资链路可正常进入原有业务页面。
- 发布职位模板入口和分步骤表单不破坏原有提交数据。
- 登录拦截、退出登录和未登录跳转仍然正常。
- 页面无明显横向溢出，小程序构建通过。

## 后续实施建议

建议分三阶段实施：

1. 信息架构阶段：新增 TabBar、重组工作台、流程、待办、我的四个主入口。
2. 核心业务阶段：重做职位、报名、排班、考勤、薪资页面和发布职位表单。
3. 全量统一阶段：重做基础管理、账号、余额、设置、认证和登录页面，并统一组件细节。
