# 后端技术规范

## 1. 适用范围

本文档适用于本项目 3 个后端服务：

- `c-service`：工人端后端，默认端口 `8082`
- `enterprise-service`：企业端后端，默认端口 `8081`
- `platform-service`：平台端后端，默认端口 `8083`

后端统一使用 Java 17、Spring Boot、Spring Security、MyBatis、MySQL。新增功能应优先沿用现有分层、命名和返回结构，不做无关重构。

## 2. 代码目录结构说明

各后端服务整体目录保持一致：

```text
<service>/
├── src/main/java/com/parttime/<module>/
│   ├── config/          # 安全、跨域、JWT、框架配置
│   ├── controller/      # HTTP API 入口
│   ├── service/         # 业务接口
│   ├── service/impl/    # 业务实现
│   ├── mapper/          # MyBatis Mapper 接口
│   ├── pojo/
│   │   ├── entity/      # 数据库实体
│   │   ├── vo/          # 响应对象
│   │   └── cmd/         # 请求参数对象
│   └── filter/          # 过滤器
├── src/main/resources/
│   ├── mapper/          # MyBatis XML
│   └── application*.yml # 环境配置
└── src/test/java/       # 单元测试 / 控制器测试 / XML 规则测试
```

目录职责：

- `controller` 只处理认证上下文、参数接收、参数校验和调用 service。
- `service` 定义业务能力，`service/impl` 实现业务流程和事务边界。
- `mapper` 只定义数据访问方法，不承载业务判断。
- `pojo/entity` 对应数据库表字段，也可包含查询辅助字段。
- `pojo/vo` 面向前端返回，禁止直接把内部不需要的敏感字段暴露给前端。
- `pojo/cmd` 面向请求入参，新增写操作优先使用 cmd 承载请求体。

## 3. URL 规范

### 3.1 基础路径

- 工人端接口统一使用 `/api/...`。
- 企业端前端请求基础路径为 `/api`，Controller 内按模块定义路径。
- 平台端接口同样按 `/api/...` 组织。

### 3.2 命名规则

- URL 使用小写英文和短横线，避免大小写混用。
- 模块资源使用名词复数或稳定业务名词，例如：
  - `/api/jobs`
  - `/api/attendance`
  - `/api/earnings/transactions`
  - `/api/settings`
- 当前登录用户相关接口可使用 `/my`：
  - `/api/jobs/applications/my`
  - `/api/attendance/my`
- 详情资源使用路径参数：`/{id}`。
- 查询条件使用 query 参数：`?page=1&pageSize=20`。
- 写操作请求体使用 JSON。

### 3.3 HTTP 方法

- `GET`：查询列表、详情、统计信息。
- `POST`：创建资源、提交业务动作。
- `PUT`：整体更新或保存配置。
- `PATCH`：局部更新，只有现有模块已有相同风格时使用。
- `DELETE`：删除资源。

### 3.4 分页规范

分页接口优先使用：

- `page`：从 1 开始。
- `pageSize`：每页数量。
- 返回结构优先使用 `PageVO`，包含 `records` 和 `total`。

## 4. Controller 规范

Controller 负责 API 编排，不写复杂业务逻辑。

要求：

- 类名以 `Controller` 结尾。
- 使用 `@RestController` 和 `@RequestMapping` 定义模块路径。
- 方法按业务语义命名，避免 `doXXX`、`handleXXX` 等模糊命名。
- 当前登录用户 ID 从 Spring Security 上下文或统一认证工具中获取，不从前端传入。
- 入参优先使用 `@RequestBody` + cmd 对象承载复杂参数。
- 查询参数使用 `@RequestParam`，不要使用`@PathVariable`这种路径参数。
- Controller 不直接访问 Mapper。
- Controller 不返回数据库 Entity，优先返回 VO，禁止用map返回，用ApiResponse包装。
- 错误处理遵循现有全局异常或当前模块约定，不在 Controller 中堆叠大量 try/catch。
- Controller 的函数只能用@GetMapping和@PostMapping注解，禁止使用@DeleteMapping和@PutMapping，当使用@PostMapping注解时，只能用@RequestBody作为入参

示例结构：

```java
@RestController
@RequestMapping("/api/example")
public class ExampleController {
    @Resource
    private ExampleService exampleService;

    @GetMapping("/my")
    public ExampleVO getMyExample() {
        Long userId = getCurrentUserId();
        return exampleService.getMyExample(userId);
    }
}
```

## 5. Service 规范

Service 是业务逻辑和事务边界所在。

要求：

- 接口放在 `service`，实现放在 `service/impl`。
- 实现类使用 `@Service`。
- 涉及多表写入、余额变更、结算、撤销等操作必须使用 `@Transactional`。
- Service 可以调用多个 Mapper，但不要把 SQL 拼接逻辑写在 Service。
- Service 负责 Entity 到 VO 的转换，必要时提取私有转换方法。
- 涉及金额时使用 `BigDecimal`，禁止使用 `double` 或 `float`。
- 涉及时间时使用 `LocalDate`、`LocalTime`、`LocalDateTime`，返回给前端时按现有格式转为字符串。
- 不在 Service 中打印 token、密码、银行卡完整号等敏感信息。
- **禁止在 for/while/stream 循环体内执行数据库读操作（N+1 问题）**。批量读取应在循环外通过 `batchXxx` 方法完成，再在循环内使用内存 Map 做 join。写操作（insert/update/upsert）在事务内单条写是合理的。

### 5.1 Entity 规范

Entity 是数据库表的映射，**仅保留表字段**，不包含关联数据。

要求：

- Entity 字段必须与数据库表字段一一对应。
- **禁止在 Entity 中添加关联字段**（如 `companyName`、`jobTitle`、`workerName` 等）。
- 关联数据由 Service 层批量加载后通过内存 Map 关联，填充到 VO 中。

示例：

```java
// ✅ 正确：Entity 仅包含表字段
@Data
public class Job {
    private Long id;
    private Long companyId;
    private String title;
    private Long categoryId;
    // ...
}

// ❌ 错误：Entity 包含关联字段
@Data
public class Job {
    private Long id;
    private Long companyId;
    private String companyName;    // 关联字段，禁止
    private String categoryName;   // 关联字段，禁止
    // ...
}
```

### 5.2 VO 规范

VO 面向前端返回，**包含 Entity 字段 + 关联数据字段**。

要求：

- VO 继承或包含 Entity 的基础字段。
- 关联数据字段（如 `companyName`、`jobTitle`）放在 VO 中。
- Service 层负责将 Entity 转换为 VO，并填充关联数据。

示例：

```java
@Data
public class JobVO {
    private Long id;
    private Long companyId;
    private String title;
    private Long categoryId;
    // 关联数据字段
    private String companyName;
    private String categoryName;
    private List<JobRateVO> rates;
    // ...
}
```

### 5.3 批量加载 + 内存关联模式

解决 N+1 问题的标准模式：**批量加载 → 内存 Map → 循环填充**。

```java
// 1. 批量加载所有需要的数据
List<Long> jobIds = shifts.stream().map(Shift::getJobId).distinct().toList();
Map<Long, Job> jobMap = jobMapper.findByIds(jobIds).stream()
        .collect(Collectors.toMap(Job::getId, j -> j));

// 2. 循环中使用 Map 关联，不查数据库
for (Shift shift : shifts) {
    Job job = jobMap.get(shift.getJobId());
    vo.setJobTitle(job != null ? job.getTitle() : null);
}
```

批量查询方法命名约定：

| 方法 | 说明 |
|---|---|
| `findByIds(List<Long> ids)` | 按 ID 列表查询 |
| `findByXxxIds(List<Long> xxxIds)` | 按外键列表查询（如 `findByJobIds`） |
| `findByWorkerIds(List<Long> workerIds)` | 按工人 ID 列表查询 |
| `batchInsert(...)` | 批量插入 |

### 5.4 新增字段同步清单

新增字段时必须同步以下文件：

1. 数据库迁移脚本（`scripts/`）
2. Entity 字段（仅表字段）
3. VO/CMD 字段（含关联字段）
4. Mapper XML 查询列或写入列
5. Service 映射逻辑（批量加载 + 内存关联）
6. Controller 或 Service 测试

## 6. Mapper 规范

Mapper 接口与 XML 必须一一对应。

要求：

- Mapper 接口放在 `src/main/java/.../mapper/`。
- XML 放在 `src/main/resources/mapper/`。
- XML namespace 必须等于 Mapper 接口全限定名。
- 方法参数超过一个时使用 `@Param` 明确命名。
- 查询列表必须有明确排序，不能依赖数据库默认顺序。
- 分页查询使用 `LIMIT #{pageSize} OFFSET #{offset}` 或沿用当前模块分页方式。
- 多表查询字段冲突时必须使用别名，并保证能映射到 Entity/VO 字段。
- 动态 SQL 避免字符串拼接，使用 MyBatis 标签或参数绑定。
- 禁止把用户输入直接拼到 SQL 中，必须使用 `#{}` 参数绑定。

### 6.1 批量查询方法

为支持 Service 层批量加载 + 内存关联模式，Mapper 应提供以下批量查询方法：

```java
@Mapper
public interface JobMapper {
    // 单条查询
    Optional<Job> findById(Long id);

    // 批量查询（必须提供）
    List<Job> findByIds(@Param("ids") List<Long> ids);

    // 按外键批量查询（按需提供）
    List<Job> findByCompanyId(@Param("companyId") Long companyId);
}
```

XML 实现：

```xml
<select id="findByIds" resultMap="JobResultMap">
    SELECT * FROM jobs WHERE id IN
    <foreach collection="ids" item="id" open="(" separator="," close=")">
        #{id}
    </foreach>
</select>
```

### 6.2 批量插入方法

循环 INSERT 应改为批量插入：

```java
@Mapper
public interface JobTagRelationMapper {
    int batchInsert(@Param("jobId") Long jobId, @Param("tagIds") List<Long> tagIds);
}
```

XML 实现：

```xml
<insert id="batchInsert">
    INSERT INTO job_tag_relations (job_id, tag_id)
    VALUES
    <foreach collection="tagIds" item="tagId" separator=",">
        (#{jobId}, #{tagId})
    </foreach>
</insert>
```

### 6.3 单表查询原则

Entity 对应的查询应使用**单表查询**，关联数据由 Service 层批量加载：

```xml
<!-- ✅ 正确：单表查询 -->
<select id="findById" resultMap="JobResultMap">
    SELECT * FROM jobs WHERE id = #{id}
</select>

<!-- ❌ 错误：包含 JOIN 的查询（关联数据应由 Service 层加载） -->
<select id="findById" resultMap="JobResultMap">
    SELECT j.*, c.name AS company_name
    FROM jobs j
    LEFT JOIN enterprises c ON j.company_id = c.id
    WHERE j.id = #{id}
</select>
```

例外：分页列表查询（如 `findHours`）可保留 JOIN 以减少查询次数。

## 7. 数据库规范

### 7.1 命名

- 表名使用小写下划线复数或稳定业务名词，例如 `attendance_records`、`balance_transactions`。
- 字段名使用小写下划线，例如 `worker_id`、`created_at`。
- 主键统一使用 `id`。
- 外键字段使用 `<业务对象>_id`，例如 `job_id`、`worker_id`、`company_id`。
- 状态字段使用明确枚举字符串，例如 `PAID`、`UNPAID`、`PENDING`、`APPROVED`。

### 7.2 通用字段

业务表建议包含：

- `id`
- `created_at`
- `updated_at`
- 必要的状态字段，如 `status`、`settlement_status`

是否添加 `deleted_at` 或逻辑删除字段，应跟随现有模块风格，不单独引入新风格。

### 7.3 金额与时间

- 金额使用 `DECIMAL`，Java 中使用 `BigDecimal`。
- 日期使用 `DATE`，时间段使用 `TIME`，时间戳使用 `DATETIME`。
- 数据库和接口展示要注意时区，本项目面向展示时通常转为北京时间字符串。

### 7.4 索引

以下字段通常需要索引：

- 高频查询条件：`worker_id`、`company_id`、`job_id`、`shift_id`。
- 外键关联字段：`related_attendance_record_id`、`related_withdrawal_id`。
- 列表排序字段：`created_at`、业务日期字段。
- 唯一约束根据业务确定，例如同一工人同一排班只能有一条报名或考勤记录。

### 7.5 迁移脚本

- 新增表、字段、索引必须提供 SQL 脚本，放在 `scripts/` 或当前服务既有迁移目录。
- 脚本命名使用序号 + 业务含义，例如 `15_repair_earnings_attendance_links.sql`。
- 涉及历史数据修复时，脚本必须可重复理解，避免误更新无关数据。
- 执行 SQL 时使用 utf8mb4：

```bash
mysql --default-character-set=utf8mb4 -h localhost -P 3306 -u part_time_work -ppassword123 part_time_work < scripts/<file>.sql
```

## 8. 安全与跨域

- 认证统一使用 JWT + Spring Security。
- 需要登录的接口不得信任前端传入的用户 ID。
- CORS 配置应覆盖开发和生产来源：`localhost`、`127.0.0.1`、`121.199.12.23`。
- 必须放行必要的 `OPTIONS` 预检请求。
- 禁止提交密钥、密码、token、线上敏感配置。

## 9. 测试与验证

后端改动完成后，按影响范围运行：

```bash
cd c-service && JAVA_HOME=$(/usr/libexec/java_home -v 17 2>/dev/null) mvn test
cd enterprise-service && JAVA_HOME=$(/usr/libexec/java_home -v 17 2>/dev/null) mvn test
cd platform-service && JAVA_HOME=$(/usr/libexec/java_home -v 17 2>/dev/null) mvn test
```

提交前必须运行：

```bash
git diff --check
```

后端新增接口或字段时，至少补充以下一种验证：

- Controller 测试验证接口返回。
- Service 测试验证业务规则。
- Mapper XML 测试验证 SQL 结构约定。
- 本地接口联调验证，并记录必要的迁移脚本。

## 10. 提现功能

### 10.1 新增接口

- `GET /api/withdrawal-methods` - 获取可用提现方式
- `GET /api/bank-cards` - 获取银行卡列表

### 10.2 修改接口

- `POST /api/withdrawals` - 申请提现（增加 withdrawalMethod 参数）

### 10.3 提现方式

- `WECHAT` - 微信零钱
- `BANK_CARD` - 银行卡

### 10.4 限制

- 最低提现金额：1元
- 最高提现金额：1000元
- 每日提现次数：最多3次
