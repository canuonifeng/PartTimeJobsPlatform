## 1. 项目全景概述

### 1.1 平台定位

「老登e站」是一个连接零工市场/驿站等用工方与兼职求职者的数字化平台。核心价值：**用工方快速招到靠谱兼职人员，工人快速找到靠谱零活**。

#### 2.2 核心业务流程验证

**MVP 全链路走通测试用例（7 步核心流程）：**

```
Step 1: 企业入驻
  └─ 零工市场/驿站注册 → 企业认证 → 完善资质信息
  └─ 运营后台审核通过 → 企业可发布职位

Step 2: 兼职入驻
  └─ 工人注册 → 实名认证 → 绑定银行卡
  └─ 完善个人信息（技能/偏好/联系方式）

Step 3: 企业自主排班 + 兼职报名排班
  └─ [企业] 发布职位 → 创建排班（日期/时段/人数/薪资）
  └─ [兼职] 浏览职位 → 按时间/地点/薪资筛选 → 一键报名
  └─ [企业] 审核报名 → 确认录用 → 排班锁定

Step 4: 自动投保
  └─ 排班确认后 → 系统自动调用保险接口
  └─ 为每位兼职人员投保当日意外险
  └─ 保费自动扣除（详见保费承担方案对比）

Step 5: 兼职打卡
  └─ 签到：到达工作地点 → 定位打卡（记录时间/地点）
  └─ 签退：工作结束 → 定位打卡（记录工时）
  └─ 异常处理：迟到/早退/缺勤/定位偏差

Step 6: 薪资结算（个税扣除）
  └─ 企业确认工时 → 系统自动计算薪资
  └─ 个税扣除（按国家个税标准计算）
  └─ 生成结算单 → 企业确认 → 冻结资金

Step 7: 兼职提现
  └─ 工人查看已结算收入 → 发起提现
  └─ 企业端审核 → 打款（T+0/T+1）
  └─ 工人银行卡到账 → 提现完成通知
```

#### 📌 保费承担方案对比（待决策者确认）

| 方案 | 承担方 | 成本估算(100单) | 优点 | 缺点 | 适用阶段 |
|------|--------|-------------------|------|------|---------|
| **A：企业承担** | 用工企业 | 50~200元 | 工人无感知体验好；用工风险理应由企业负责 | 增加企业成本，可能影响入驻意愿 | 增长期/成熟期 |
| **B：个人承担** | 兼职人员 | 50~200元 | 平台零成本；按天保费低(0.5~2元/天) | 工人有感知，低价岗位可能不满 | 不推荐单独使用 |
| **C：平台补贴** | 平台 | 50~200元 | 体验最好，快速起量 | 冷启动期增加成本负担 | 冷启动期 |
| **D：企业承担+平台补贴过渡** | 企业+平台 | 视分摊比例 | 兼顾体验和成本；冷启动平台兜底，稳定后转企业 | 规则略复杂，需系统支持 | 推荐方案 |

**推荐方案 D**：冷启动期平台补贴保费，培养企业和工人使用习惯；稳定后转为企业承担，平台提供保费优惠套餐（买月卡送保险等），降低企业抵触。

> ⚠️ 保费按天投保，行业标准约 0.5~2 元/人/天，保额通常为 10~50 万元意外险。

**演示数据准备（覆盖 MVP 7 步）：**

| 数据类型 | 数量 | 说明 |
|----------|------|------|
| 零工市场/驿站 | 3~5 家 | 不同规模（大型市场/社区驿站/企业自营） |
| 招聘岗位 | 10~20 个 | 每家企业 3~5 个岗位（分拣/服务员/促销等） |

| 投保记录 | 50+ 条 | 与排班关联的自动投保记录 |
| 考勤记录 | 30+ 条 | 含正常/迟到/早退/缺勤/定位异常 |

### 3.2 CI/CD 流程

```
开发者提交代码 → GitHub Push
        ↓
GitHub Actions / Webhook 触发
        ↓
自动构建（mvn clean package / npm run build）
        ↓
运行单元测试 → 失败则通知开发者
        ↓
自动部署到测试环境
        ↓
集成测试通过
        ↓
手动触发 → 部署到预发布环境
        ↓
线上发布（滚动更新，零停机）
```

### 3.3 数据库变更规范

```
1. 新增脚本按顺序命名 scripts/28_xxx.sql
2. 脚本必须可重复执行（CREATE IF NOT EXISTS / ALTER 兼容）
3. 执行线上脚本前先在测试环境跑一遍
4. DDL 变更选在低峰期（凌晨）执行
5. 变更后重启对应服务
```
