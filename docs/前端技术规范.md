# 前端技术规范

## 1. 适用范围

本文档适用于本项目 4 个前端应用：

- `worker-uniapp`：工人端 UniApp，支持微信小程序和 H5。
- `enterprise-uniapp`：企业端 UniApp，支持微信小程序和 H5。
- `enterprise-pc`：企业 PC 管理端，Vue 3 + Element Plus。
- `platform-pc`：平台 PC 管理端，Vue 3 + Element Plus。

前端开发应优先沿用现有目录、组件风格、接口封装和构建方式，不做无关重构。

## 2. 应用目录结构

### 2.1 UniApp

典型结构：

```text
<uniapp>/
├── src/
│   ├── api/          # 接口封装
│   ├── pages/        # 页面
│   ├── store/        # 状态管理
│   ├── static/       # 静态资源
│   ├── App.vue       # 应用入口
│   └── main.js       # Vue 入口
├── package.json
└── vite.config.js
```

约定：

- 页面按业务模块放在 `src/pages/<module>/`。
- 接口按业务模块放在 `src/api/`。
- 页面只负责展示、交互和轻量数据组装，复杂规则优先下沉到工具函数或后端。
- 路由路径必须与 UniApp 页面配置保持一致。

### 2.2 PC 管理端

典型结构：

```text
<pc>/
├── src/
│   ├── api/          # Axios 接口封装
│   ├── views/        # 页面视图
│   ├── components/   # 复用组件
│   ├── router/       # 路由
│   ├── stores/       # Pinia 状态
│   ├── utils/        # 工具函数
│   ├── App.vue
│   └── main.js
├── .env.development
├── .env.production
└── package.json
```

约定：

- 页面级组件放 `views`，跨页面复用组件放 `components`。
- 接口统一经 `api` 封装，不在页面中硬编码完整 URL。
- 管理端优先使用 Element Plus 现有组件和项目已有布局方式。

## 3. 接口请求规范

### 3.1 基础地址

开发环境使用 `localhost`，生产环境使用 `121.199.12.23`：

- 工人端：开发 `http://localhost:8082`，生产 `http://121.199.12.23:8082`
- 企业端：开发 `http://localhost:8081/api`，生产 `http://121.199.12.23:8081/api`
- 平台端：开发 `http://localhost:8083/api`，生产 `http://121.199.12.23:8083/api`

不得在业务页面中写死生产地址。

### 3.2 API 封装

- 每个业务模块单独封装 API 文件，例如 `jobs.js`、`attendance.js`、`earnings.js`。
- 页面调用 API 函数，不直接调用 `uni.request` 或 `axios`。
- GET 查询参数通过封装方法传入对象，由 request 层清理空参数。
- POST/PUT 请求体使用 JSON 对象。
- 接口命名使用业务动作，例如 `getEarningsTransactions`、`getMyAttendance`。

### 3.3 Token 与登录态

- Token 从本地存储读取，并统一放在 `Authorization: Bearer <token>`。
- 401 响应统一清理登录态并跳转登录页。
- 页面内不要重复实现 401 处理。
- 不在控制台输出 token、手机号、银行卡号等敏感信息。

### 3.4 错误处理

- 页面加载失败时使用 `uni.showToast` 或管理端消息组件提示。
- 列表接口失败时避免展示 mock 数据冒充真实数据。
- 空数据应展示空状态，而不是硬编码示例数据。
- 对用户可恢复的错误给明确提示，例如“收入明细加载失败”。

## 4. 页面与组件规范

### 4.1 页面职责

页面负责：

- 调用 API 获取数据。
- 维护当前页面的 loading、分页、筛选状态。
- 将后端字段转换为展示文案。
- 处理用户点击、跳转、提交。

页面不应负责：

- 复杂跨模块业务判断。
- 重复实现接口鉴权。
- 写死大量测试数据。
- 直接修改其他页面内部状态。

### 4.2 组件拆分

当页面出现以下情况时，应考虑拆组件：

- 同一 UI 块在多个页面复用。
- 单个 `.vue` 文件过长且包含多个独立区域。
- 列表卡片、筛选栏、表单区域逻辑相对独立。

组件要求：

- Props 命名清晰，避免传入整页状态。
- 事件使用业务语义命名，如 `submit`、`refresh`、`select`。
- 不在组件内部直接操作全局路由或全局状态，除非该组件本身就是导航/布局组件。

## 5. UniApp 规范

### 5.1 兼容性

UniApp 页面应优先兼容微信小程序：

- 样式避免依赖 H5 专属能力。
- 布局优先使用 `view`、`text`、`button` 等小程序兼容组件。
- 单位优先使用 `rpx`。
- 避免使用浏览器专属 API，如 `window`、`document`。
- 需要条件编译时应保持清晰，不要在同一逻辑内混杂多个端的特殊处理。

### 5.2 生命周期

- 首屏数据通常在 `onMounted` 或页面生命周期中加载，跟随现有页面风格。
- 页面返回后需要刷新时，优先使用已有事件机制或页面生命周期。
- 下拉刷新、触底加载要维护 loading 状态，避免重复请求。

### 5.3 样式

- 样式使用 scoped 或当前页面已有方式。
- 颜色、间距、圆角跟随同页面已有视觉风格。
- 列表信息较多时优先换行清晰展示，不把岗位、日期、地址等长文本挤在一行。
- 长文本要考虑换行或省略，避免撑破小程序页面。

## 6. PC 管理端规范

### 6.1 Vue 与 Element Plus

- 使用 Vue 3 Composition API 或项目当前页面已有写法。
- 表格、表单、弹窗、分页优先使用 Element Plus。
- 表单校验使用 Element Plus rules 或项目已有校验方式。
- 复杂页面保持“查询区 + 表格 + 弹窗/抽屉”的管理端常见结构。

### 6.2 路由与权限

- 新页面必须补充路由配置。
- 需要权限控制的页面按现有权限方案接入。
- 登录态失效由请求封装或路由守卫统一处理，不在页面中散落处理。

### 6.3 表格与分页

- 列表接口参数统一包含页码和每页数量。
- 表格排序、筛选条件应体现在请求参数中。
- 删除、审核、结算等危险操作必须二次确认。
- 操作成功后刷新当前列表，不强制回到第一页，除非业务明确要求。

## 7. 数据展示规范

### 7.1 金额

- 金额展示统一带 `¥` 或根据页面现有风格展示。
- 计算金额时避免浮点误差，复杂金额计算优先由后端完成。
- 前端只做展示格式化和简单求和。

### 7.2 日期与时间

- 后端已返回格式化时间时，前端直接展示。
- 日期和时间段分开语义展示，例如“2026-06-05 09:00-18:00”。
- 列表排序应使用稳定字段，例如 `createdAt`、业务日期、开始时间。
- 不依赖数组原始顺序，除非后端明确保证排序。

### 7.3 状态

- 状态值来自后端枚举，前端做中文映射。
- 映射函数要包含默认值，避免未知状态导致页面空白。
- 状态样式与业务语义一致，例如成功、待处理、失败、已结算、待结算。

## 8. 表单规范

- 提交前做必要的必填校验。
- 手机号、金额、日期等基础格式在前端校验，最终规则以后端为准。
- 提交按钮要防重复点击。
- 提交成功后给出反馈，并按业务返回上一页或刷新当前页。
- 不在前端信任用户 ID、企业 ID、工人 ID 等敏感身份字段。

## 9. 构建与验证

### 9.1 工人端 UniApp

```bash
cd worker-uniapp && npm run build:h5
cd worker-uniapp && npm run build:mp-weixin
```

### 9.2 企业端 UniApp

```bash
cd enterprise-uniapp && npm run build:mp-weixin
```

### 9.3 PC 管理端

```bash
cd enterprise-pc && npm run build
cd platform-pc && npm run build
```

### 9.4 提交前检查

```bash
git diff --check
```

构建产物 `dist/` 不允许提交。

## 10. 已知非阻塞提示

以下构建 warning 通常不阻塞提交：

- Dart Sass `legacy-js-api` deprecation warning。
- Rollup 对 `/* #__PURE__ */` 注释的 warning。

如果出现 TypeScript、模板编译、依赖缺失、接口路径错误等 error，必须修复后再提交。
